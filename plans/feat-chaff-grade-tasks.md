# chaff grade — 問題の種類ごとの採点基準（tasks）

issue: #1167（3 番目の項目）

## 何のためか

ベンチマークは要約・抽出・計算・文書作成など、種類の違う問題を混ぜる。種類ごとに基準を変えたい。

## 決めたこと

- **基準に `tasks: { <名前>: <基準> }`。** 各値は最上位と同じ形（`tasks` だけは書けない。入れ子は「知らないキー」で止まる）。
  chaff.yaml の `grade:` でも `--rubric` のファイルでも同じ。裸の `<名前>:` は何も書いていない基準で、最上位をそのまま継ぐ。
- **重ね方。** task が書いたキーは最上位のそのキーを丸ごと置き換え、書かないキーは最上位を継ぐ。
  `facts` `citations` `contexts` は中の欄ごとには混ぜない（task の `facts` が最上位の `facts` を置き換える）。
  `rules` だけは規則 id ごと: task が書いた id の項目が最上位の同じ id の項目を置き換え、ほかの id は最上位のまま効く。
- **項目に `"task": "<名前>"`。** 基準に無い名前、文字列でない値、空文字は入力の誤り（exit 2、行と欄を出す）。
  最上位に黙って落とさない。`task` の無い項目は最上位の基準で、結果はこれまでと同じ。
  `task` は項目の欄なので `--variant-key task` には使えない。
- **結果に `task`。** 項目が task を名指したときだけ結果の行に `task` が入る。集計で種類ごとに分けられる。
  文字の要約は変えない。
- **stamp。** 基準は（tasks ごと）既に stamp に入っている（chaff.yaml の `grade:` そのもの、またはファイルの hash）。
  task の基準だけを変えても settings の hash が変わることをテストで確かめる。
- **`--baseline` の「基準にある規則」** は出力ごとに決める: その出力の task の基準（重ねた後）が名指す規則が
  増えたときだけ後退とする。別の task だけが名指す規則が増えても後退にしない。知らない規則 id の警告は
  `grade.tasks.<名前>.rules.<id>` と書かれた場所を出す。
- 重ね方は純粋な `grade/task-rubric.ts`。読むのは `grade/rubric.ts`、項目の `task` は `grade/item.ts`。

## 範囲外

- `chaff grade` 以外の API（`grade()`）から task を渡すこと。
- 文字の要約を task ごとに分けること。ガイドのページ（#1167 の 4 番目）。

# chaff grade: 問いごとの正解（expect）

issue: #1167 の 2（ベンチマークの採点）

## 何のためか

抜き出しや計算の問いには決まった答えがある。今はそれを確かめられるのがモデルか人だけなので、items.jsonl の 1 行に
`"expect": { "facts": ["12,000円", "2026年3月31日"], "absent": ["15,000円"] }` を書けば、chaff が機械で確かめる。

## 決めたこと

- **照らし方は compare と同じ。** 各項目を compare が文書を読むのと同じ道（`documentFromSource` → `factsOf`）で読み、
  出力に同じ事実があるかを `outcomeOf(…, "distinct")` で決める。新しい正規化は書かない。だから 12,000円 と 12000円、
  2026年3月31日 と 2026-03-31 は同じで、compare が別の事実と読むもの（¥12,000 と 12,000円、1万2000円）は別のまま。
- **項目はちょうど 1 つの事実。** 事実が無い（hello）か 2 つ以上（1万2000円 は 2000円 と 1 に読まれる）項目は入力の誤りで、
  その行番号と `expect.facts[0]` のような場所を出して exit 2。黙って通さない。2 つ以上のうち 1 つが項目の文全体なら
  それを取る（「12,000円」は引用と中の数に読まれ、項目は引用を指す）。
- **読む言語とジャンルは出力のもの。** 項目は出力と同じ言語・ジャンルで読むので、同じ事実が同じ鍵になる。
- **欄の形の誤り**（オブジェクトでない、facts / absent 以外のキー、空でない文字列の並びでない）も入力の誤りで exit 2。
  知らないキーを無視すると、綴り違いの一覧が何も確かめずに全部通すため。空の一覧と `{}` は「確かめるものが無い」。
- **引用の中の事実も数える。** compare は引用の中の数も事実として読むので、引用の中にだけ 12,000円 がある出力は
  facts を満たし、absent にも当たる。
- **落ちた理由**は `expect.missing <項目>` と `expect.present <項目>`。重みは無い。`grade:` があっても無くても、
  expect を持つ項目には必ず効く（`grade:` の鍵は足さない。rubric ファイルの読み込みは #1171）。
- **結果の行**には expect を持つ項目だけ `expect: { checked, missing, present }` を足す。無い項目の結果は今までと同じ形。
  `--baseline` で読み戻す結果にもこの欄を確かめる。

## 確かめ方

- `test/test_grade_expect.ts`: 欄の形、1 つの事実の取り方、日英それぞれで書き方の違う一致・欠け・あってはならない事実・
  読めない項目・空の一覧・型の誤り・引用の中の事実。
- expect の無い入力で出力が変わらないこと: 変更前と変更後のビルドで、site の ai-evals の入力、examples/evals/openai-evals
  から作った入力、それらを組み合わせて生成した入力、誤りのある入力を、text / json / compact / markdown と `--out`、
  `grade:` の有無、日英で走らせ、出力を突き合わせる。
- `yarn typecheck`、grade のテスト、`yarn corpus`、`yarn planted`。

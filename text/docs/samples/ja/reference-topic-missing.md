# 「第2章で述べた〇〇」の〇〇が、第2章に無い（`reference-topic-missing`）

**こんな文書に:** 社員の手引き、製品の説明書、提案書。章を入れ替えたり、話を別の章へ移したりしたときに、「第2章で述べた」の番号が古いまま残ります。

## 元の文章

```markdown chaff-before
# 新しく入った人の手引き

## 第1章 初日にすること

入館証を受け取り、社内のアカウントを作ります。
アカウントを作ったら、パスワードを変えてください。

## 第2章 勤怠の記録

出社したときと帰るときに、勤怠の画面で打刻します。
打刻を忘れたときは、その週のうちに上司に申し出てください。

## 第3章 休暇の取り方

有給休暇は、取る日の3日前までに勤怠の画面から申請します。
申請するときは、第1章で述べた打刻の画面と同じ画面を使います。
```

## 直した文章

```markdown chaff-after
# 新しく入った人の手引き

## 第1章 初日にすること

入館証を受け取り、社内のアカウントを作ります。
アカウントを作ったら、パスワードを変えてください。

## 第2章 勤怠の記録

出社したときと帰るときに、勤怠の画面で打刻します。
打刻を忘れたときは、その週のうちに上司に申し出てください。

## 第3章 休暇の取り方

有給休暇は、取る日の3日前までに勤怠の画面から申請します。
申請するときは、第2章で述べた打刻の画面と同じ画面を使います。
```

## 直し方

第3章は「第1章で述べた打刻の画面」と書いています。けれども第1章は初日にすることの章で、打刻の話はありません。打刻の話は第2章にあります。
読む人は第1章を読み返しても見つけられず、手引きの書き方そのものを疑います。

話は第2章にあるので、参照の番号を「第2章」に直しました。
chaff は、「で述べた」「で説明した」に続く語を、参照先の章の見出しと本文から探します。言い換えて書いた語（料金と価格）は同じ話と見つけられないので、語をそろえておくと、読み手も探せます。

## 設定

ふだんは「参考」として出します。`strict` にすると「注意」になります。

```yaml chaff-settings
rules:
  reference-topic-missing: strict
```

「詳細」「内容」のように、どの章にも当てはまる語は見ません。
参照先が見出しを持たないか一つに決まらない参照、他の文書の条も見ません。
どのジャンルでも動きます。

```text chaff-explain
$ npx chaffjs explain reference-topic-missing --genre docs/manual

  直しかた: 話がどの章にあるかを確かめて、参照の番号を直してください。言い換えて書いているなら、同じ言葉に揃えると読み手が探せます。

  書き直しの深さ: light（語と文を直す。構成と文体は残す）。chaff fix-plan --depth でこれより浅い深さを選ぶと、計画はこのルールを直さず、名前だけを挙げます。

  設定できる値（数える上限は無く、指摘の重さが変わります）:
    strict   注意
  → normal   参考
    relaxed  参考
    off      見ない

  いまは normal です。

  変える:  npx chaffjs relax reference-topic-missing --why "理由"
```

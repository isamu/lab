# 閉じていないコードブロック（`unclosed-code-fence`）

**こんな文書に:** 開発の手引き、操作マニュアル、社内の技術メモ。コードを貼り付けたあと、閉じる「```」を書き忘れる形がよくあります。

## 元の文章

````markdown chaff-before
# 開発用パソコンの準備

新しく配属された人が、最初の日に行う準備の手順です。

## 必要なものを入れる

端末を開き、次のコマンドで必要なものを入れます。

```sh
brew install git node

## 動くことを確かめる

`node --version` と打って、版の番号が表示されれば準備は終わりです。
````

## 直し方

この手引きでは、コマンドを「```sh」で始めたまま、閉じる「```」がありません。
Markdown は、閉じていないコードブロックを、文書の終わりまで続くものとして表示します。
後ろの「動くことを確かめる」という見出しも、その下の説明も、等幅の字の塊になってしまいます。
新しく配属された人には、手引きが壊れて見え、最後の確かめの手順を見落とします。

直した文章では、コマンドの次の行に「```」を足して、コードブロックを閉じました。

## 設定

この規則は、指摘の重さだけが変わります。ふだんは「注意」として出し、`strict` で「エラー」、`relaxed` で「参考」になります。

```yaml chaff-settings
rules:
  unclosed-code-fence: strict
```

閉じたコードブロック、字下げで書いたコードブロック、引用の中のコードブロックは指しません。
どのジャンルでも動きます。

```text chaff-explain
$ npx chaffjs explain unclosed-code-fence --genre docs/manual

  閉じていないコードブロック   (unclosed-code-fence)

  「```」で始めたコードブロックを閉じ忘れると、Markdown は文書の終わり（リストの項目の中ならその項目の終わり）までをすべてコードとして表示します。後ろの見出しも本文も等幅の字の塊になり、読み手には文書が壊れて見えます。

  直しかた: コードの終わりに、始めと同じ記号を同じ数以上並べた行（「```」）を足してください。

  書き直しの深さ: light（語と文を直す。構成と文体は残す）。chaff fix-plan --depth でこれより浅い深さを選ぶと、計画はこのルールを直さず、名前だけを挙げます。

  設定できる値（数える上限は無く、指摘の重さが変わります）:
    strict   エラー
  → normal   注意
    relaxed  参考
    off      見ない

  いまは normal です。

  変える:  npx chaffjs relax unclosed-code-fence --why "理由"
```

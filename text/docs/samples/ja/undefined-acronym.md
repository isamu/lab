# 説明のない略語（`undefined-acronym`）

**こんな文書に:** 社内の報告書、会議の資料、引き継ぎのメモ。部署の中で毎日使う略語を、そのまま書きがちな文書です。

## 元の文章

```markdown chaff-before
# 上期のお問い合わせ窓口の報告

カスタマーサポート課の上期の報告です。

上期の問い合わせは一万二千件で、そのうち八割をFAQのページと電話の窓口で受けました。
電話の平均の待ち時間はAHTの見直しで三分短くなり、SLAで決めた二分以内の応答は、月に一度も破っていません。
下期は、CSATのアンケートを毎月送り、満足度の変化を追います。
```

## 直した文章

```markdown chaff-after
# 上期のお問い合わせ窓口の報告

カスタマーサポート課の上期の報告です。

上期の問い合わせは一万二千件で、そのうち八割をFAQのページと電話の窓口で受けました。
一件の対応にかかる平均の時間（AHT）を見直したことで、電話の平均の待ち時間は三分短くなりました。
お客さまとの約束（SLA）で決めた二分以内の応答は、月に一度も破っていません。
下期は、顧客満足度（CSAT）のアンケートを毎月送り、満足度の変化を追います。
```

## 直し方

元の報告は、AHT、SLA、CSATの三つの略語を説明なしで使っています。
サポート課の人には毎日の言葉でも、報告を受ける役員やほかの部署の人には、何を指しているのか分かりません。
半年後に読み返す自分にも通じないことがあります。

直した文章では、初めて出てくる所で、何のことかを日本語で書き、略語を括弧に入れました。
「一件の対応にかかる平均の時間（AHT）」のように書けば、略語を知らない人も読め、知っている人は括弧の中で確かめられます。
FAQのように誰でも知っている略語は、chaff は指しません。

## 設定

報告書（`business/report`）では、説明のない略語が二種類あると指摘します。
文書がほかの略語を自分で説明している場合は、抜けが一つでも指摘します。
`strict` にすると一種類から、`relaxed` にすると五種類からです。
ブログでは動かず、文学・論文のジャンルと話し言葉の書き起こしでも既定で止めています。

社名のように、読み手が名前として知っている略語なら、chaff.yaml の `names` に並べると説明を求めません。

```yaml chaff-settings
names:
  - SLA
```

```yaml chaff-settings
rules:
  undefined-acronym: relaxed
```

見ないことにするなら `undefined-acronym: off` です。コマンドでも変えられ、理由が chaff.yaml にコメントで残ります。

```bash
npx chaffjs relax undefined-acronym --why "部署の中だけで読む作業メモのため"
```

```text chaff-explain
$ npx chaffjs explain undefined-acronym --genre business/report

  略語が説明なしで出てくる   (undefined-acronym)

  略語は読む人によって指すものが違います。社内で通じても、半年後の自分や別の部署には通じません。

  直しかた: 初出のところで括弧に入れて展開してください。「CI（継続的インテグレーション）」のように。読み手が名前として知っている略語（社名など）なら、chaff.yaml の names に並べると求めません。

  設定できる値:
    strict   説明のない略語が 1 種類あれば指摘。文書が自分で略語を 1 個展開していれば、1 つの抜けから指摘
  → normal   説明のない略語が 2 種類あれば指摘。文書が自分で略語を 2 個展開していれば、1 つの抜けから指摘
    relaxed  説明のない略語が 5 種類あれば指摘。文書が自分で略語を 5 個展開していれば、1 つの抜けから指摘
    off      見ない

  この数字は business のもので、business/report はこれを使います。technical / speech / docs/faq / docs/manual は別の数字を持っています。

  いまは normal です。

  変える:  npx chaffjs relax undefined-acronym --why "理由"
```

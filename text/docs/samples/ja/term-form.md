# 決まった書き方と違う名前・用語（`term-form`）

**こんな文書に:** 製品やサービス、取引先の名前が出てくる手順書、リリースノート、提案書、ブログ。AI の下書きや急いだ手直しで、名前の大文字と小文字や全角と半角が崩れやすい文書です。

## 元の文章

```markdown chaff-before
# リリースの手順

1. タグを Github に送り、ビルドが終わるのを待ちます。
2. ビルドは node.js でテストを動かし、Ｊａｖａ Ｓｃｒｉｐｔのファイルを確かめます。
3. リリースノートを書いて公開します。

ビルドが失敗したら、チームのチャンネルで知らせてください。
```

```yaml chaff-config
terms:
  - GitHub
  - Node.js
  - JavaScript
```

## 直した文章

```markdown chaff-after
# リリースの手順

1. タグを GitHub に送り、ビルドが終わるのを待ちます。
2. ビルドは Node.js でテストを動かし、JavaScript のファイルを確かめます。
```

## 直し方

三つの名前には、どれも決まった書き方があります。元の文章は「Github」の h を小文字に、「node.js」の n を小文字にし、「Ｊａｖａ Ｓｃｒｉｐｔ」を全角の二語にしていました。
製品を知っている読み手には雑な文書に見え、知らない読み手は崩れた形を次の文書に写してしまいます。

この文書には正しい形が一度も出てこないので、書き方の揺れを比べる rule では比べる相手がありません。
チームは正しい形を chaff.yaml の `terms` に並べていたので、直した文章ではそれぞれを並べた形に直しました。

## 設定

この規則は、chaff.yaml の `terms` に並べた語だけを見ます。決まった書き方を、その形のまま 1 行に 1 つずつ書きます。
chaff は名前や用語の書き方を持っていません。自社の製品、取引先、記事で扱う道具の名前から、チームで並べます。

```yaml chaff-settings
terms:
  # 記事で扱う製品やサービス
  - GitHub
  - JavaScript
  - Node.js
  # 自社の名前
  - 株式会社アオバ
```

字の大小、全角と半角、ハイフン、空白だけが違う形を指します（「github」「ＧｉｔＨｕｂ」「Java-Script」「株式会社 アオバ」）。
コード、URL、メールアドレス、ファイルのパスの中は見ないので、`github.com` や `docs/github.md` は指しません。
並べた時点で書き方を決めた語なので、1 箇所でも指摘します。`relaxed` にすると 3 箇所から指摘します。

```yaml chaff-settings
rules:
  term-form: relaxed
```

コマンドや引用のように、そこだけは別の形を残すべき所は、stet で理由を添えて黙らせます。
どのジャンルでも動きます。`terms` が空なら動かず、動かなかった rule の一覧にそう出ます。

# 飾りのたとえが多い（`figurative-density`）

**こんな文書に:** 技術ブログ、操作の紹介、社内向けの手引き。仕組みを説明する所で、AI の下書きは「まるで魔法のように」「呪文のような」とたとえに逃げがちです。

## 元の文章

```markdown chaff-before
# 請求書づくりを表計算ソフトで半自動にした

毎月の請求書は、これまで取引先ごとに前の月のファイルを写して、金額を打ち直していました。
二十社で、半日かかります。
先月、作業の記録の表から請求書を作る仕組みを組んだので、手順を残しておきます。

## 仕組み

作業の記録の表には、日付、取引先、作業の内容、時間を一行ずつ書いています。
請求書のひな形で取引先の欄を選ぶと、まるで魔法のように、その月の作業が明細に並びます。
使っているのは、条件に合う行だけを抜き出す関数です。
最初は呪文のような式に見えます。
けれども、決めることは三つだけで、どの表から、どの列を、どんな条件で抜き出すかです。

## つまずいたところ

取引先の名前が、表によって「株式会社」のあるなしで違っていて、抜き出しから漏れる行がありました。
気づいたのは、二か月目です。
いまは、取引先ごとに番号を付けて、名前ではなく番号で探しています。
番号は、取引先の一覧で一番左の列に振りました。

金額の端数は、式の最後におまじないとして丸めの関数を足しています。
これを外すと、消費税の一円の違いが合計に出ます。

## 結果

先月は、二十社ぶんの請求書が一時間ほどでそろいました。
残った手作業は、明細を読み直すことと、PDFにして送ることだけです。
明細の読み直しは、続けます。
作業の内容を書き間違えた行は、式では見つけられないからです。
```

## 直し方

元の文章は、「まるで魔法のように明細に並びます」「呪文のような式」「おまじないとして丸めの関数を足しています」と、肝心の所をたとえで書いています。
読み手が知りたいのは、何がどう動くのかです。
とくに「おまじない」は、書いた本人も理由を説明できない処理に見え、次に表を引き継ぐ人が外してよいのか迷います。

直した文章では、たとえの代わりに仕組みを書きました。
「取引先の今月の行だけが抜き出されて、明細に並びます」と動きを書き、丸めの関数は「明細の行ごとの消費税を足すと、合計と一円ずれることがあるから」と理由を書いています。
「まるで魔法のように」は「まるで」と「魔法の」の二つとして数えるので、指摘は四つ出ています。

## 設定

飾りのたとえが、1000字あたり2個を超えると指摘します。短い文書（500字未満）は測りません。

```yaml chaff-settings
rules:
  figurative-density: relaxed
```

`relaxed` にすると1000字あたり3個まで、`strict` なら1個までです。
例を挙げる「〜のような」（A や B のような製品）は数えません。
文学（`literature`）と講演（`speech`）のジャンルでは、はじめから動きません。

このルールは AI らしさの目安にも数えます。文章全体の目安は `npx chaffjs ai-score post.md` で見られます。

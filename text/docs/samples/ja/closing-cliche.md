# 定型の結び（`closing-cliche`）

**こんな文書に:** 技術ブログ、体験記、会社の記事。書き終えてほっとした所で、決まった結びを付けて終えがちな文書です。

## 元の文章

```markdown chaff-before
# ビルドの待ち時間を半分にした話

社内のウェブアプリは、ビルドに毎回4分ほどかかっていました。
調べてみると、画像の圧縮をビルドのたびにやり直していたのが原因でした。

圧縮した画像を保存しておき、元の画像が変わったときだけ圧縮し直すように設定を変えました。
変えたのは設定ファイルの2行だけです。

## まとめ

これで、ビルドは2分ほどで終わるようになりました。いかがでしたか。参考になれば幸いです。
```

## 直した文章

```markdown chaff-after
# ビルドの待ち時間を半分にした話

社内のウェブアプリは、ビルドに毎回4分ほどかかっていました。
調べてみると、画像の圧縮をビルドのたびにやり直していたのが原因でした。

圧縮した画像を保存しておき、元の画像が変わったときだけ圧縮し直すように設定を変えました。
変えたのは設定ファイルの2行だけです。

## まとめ

これで、ビルドは2分ほどで終わるようになりました。
ビルドが遅いときは、毎回同じ処理をやり直していないかを先に見ると、原因が早く見つかります。
```

## 直し方

「いかがでしたか」「参考になれば幸いです」は、どの記事の終わりにも付けられる結びです。
読み手が最後に読むのに、そこには何もありません。記事の一番大事な場所を、決まり文句で使ってしまっています。

直した文章では、二つの結びを消し、本文で分かったことのうち、ほかの人にも役に立つ一つを書きました。
「毎回同じ処理をやり直していないかを先に見る」は、この記事を読んだ人が、自分のビルドでもすぐに試せることです。
本文に無い結論や呼びかけを、新しく作ってはいけません。「ぜひ試してみてください」に替えるのも、同じ決まり文句です。

## 設定

当てはまる結びが1つあれば指摘します。`relaxed` にすると、2つからです。

```yaml chaff-settings
rules:
  closing-cliche: relaxed
```

見るのは、最後の節の終わりの四段落だけです。本文の途中の「まとめると」は普通のつなぎなので指摘しません。
「参考になれば幸いです」「お気軽に〜ください」は記事でだけ指摘します。メールや提案書では、資料を添えたり問い合わせ先を言ったりする普通の文だからです。
報告書やお知らせ、法令・契約（`legal`）、説明書（`docs`）、論文（`academic`）、文学（`literature`）、話し言葉（`speech`）では動きません。

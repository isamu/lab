# ファイルによって違う定義（`cross-doc-duplicate-definition`）

**こんな文書に:** 本契約と別紙、利用規約とプライバシーポリシー、用語集と各ページ。後から一方の定義だけを書き換え、ファイルによって同じ語の意味がずれる形がよくあります。

## 元の文章

```markdown chaff-before
# 清掃業務委託契約書

株式会社あさひビル管理（以下「委託者」という。）と株式会社きらりサービス（以下「受託者」という。）は、次のとおり契約を結ぶ。

## 第1条（定義）

この契約で「対象施設」とは、委託者が管理するあさひビルの1階から5階までをいう。

## 第2条（業務）

受託者は、別紙の作業表に従い、対象施設の清掃を行う。
```

```markdown chaff-file bessi.md
# 別紙 作業表

## 1. 定義

この別紙で用いる語の意味は、次のとおりとする。

「対象施設」とは、委託者が管理するあさひビルの1階から5階まで及び地下駐車場をいう。

## 2. 作業の頻度

受託者は、対象施設の床を毎日、窓を毎月1回清掃する。
```

## 直した文章

```markdown chaff-after
# 清掃業務委託契約書

株式会社あさひビル管理（以下「委託者」という。）と株式会社きらりサービス（以下「受託者」という。）は、次のとおり契約を結ぶ。

## 第1条（定義）

この契約で「対象施設」とは、委託者が管理するあさひビルの1階から5階まで及び地下駐車場をいう。

## 第2条（業務）

受託者は、別紙の作業表に従い、対象施設の清掃を行う。
```

## 直し方

本契約は「対象施設」を「あさひビルの1階から5階まで」と定義しています。
ところが別紙の作業表は、同じ「対象施設」を「1階から5階まで及び地下駐車場」と定義しています。
受託者は、地下駐車場も毎日掃除するのかどうか、どちらの定義で読めばよいか決められません。料金に関わるので、もめたときに必ず争点になります。
別紙を作り直したときに、本契約の定義を直し忘れた、という形です。

直した文章では、本契約の定義を、別紙と同じ「1階から5階まで及び地下駐車場」に揃えました。
定義は一か所（たとえば本契約）にまとめ、別紙では「本契約第1条に定める対象施設」と引く書き方にすると、二度とずれません。
この見本では、`keiyaku.md` と `bessi.md` の二つのファイルを一度に chaff に渡しています。
二つのファイルで定義が一つずつに分かれているので、どちらが少ないとも言えず、chaff は両方のファイルを指します（上の画面は、先に表示される `bessi.md` の分です）。

## 設定

この規則は、指摘の重さだけが変わります。ふだんは「注意」として出し、`strict` で「エラー」、`relaxed` で「参考」になります。

```yaml chaff-settings
rules:
  cross-doc-duplicate-definition: strict
```

ファイルを二つ以上か、フォルダを渡したときだけ動きます。同じ語の定義（「『X』とは、…をいう」）の、語の後ろの言葉を比べ、多くのファイルと違う言葉で定義したファイルを指します。
「この条において『X』とは」のように範囲を限った定義と、意味を書かない定義（「以下『X』という。」）は比べません。全角と半角、空白、両端の句読点だけの違いは同じとみなします。
言葉が違っても意味が同じかは機械では決まらないので、確かめる場所を示すだけです。どのジャンルでも動きます。

# 見た目が同じで別の字（`lookalike-character`）

**こんな文書に:** 報告書、手順書、PDF から写した資料。PDF の字をコピーすると、見た目は同じで中身の違う字が入ります。

## 元の文章

```markdown chaff-before
# 新入社員研修の日程

人事部で、来年4月の新入社員研修の日程を決めました。

研修は4月1日から4月28日までです。
1週目は全員が本社で受け、2週目からは配属先の部署ごとに分かれます。

研修の資料は、去年の資料を⼈事部の共有フォルダから写して作ります。
各部署の担当者は、3月10日までに、研修で使う機材の数を人事部に知らせてください。
```

## 直した文章

```markdown chaff-after
# 新入社員研修の日程

人事部で、来年4月の新入社員研修の日程を決めました。

研修は4月1日から4月28日までです。
1週目は全員が本社で受け、2週目からは配属先の部署ごとに分かれます。

研修の資料は、去年の資料を人事部の共有フォルダから写して作ります。
各部署の担当者は、3月10日までに、研修で使う機材の数を人事部に知らせてください。
```

## 直し方

「⼈事部」の「⼈」は、ふつうの「人」ではなく、部首を表す字（U+2F08）です。
画面では同じに見えますが、「人事部」で検索しても、この行は見つかりません。並べ替えや辞書で引く仕組みからも漏れます。書いた人にも読む人にも、直す所が見えません。

直した文章では、その字を消して、ふつうの「人」を打ち直しました。文書全体を正規化しても直ります（部首の字は NFKC）。

## 設定

指摘の重さだけが変わります。ふだんは「注意」として出し、`strict` にすると「エラー」、`relaxed` にすると「参考」になります。

```yaml chaff-settings
rules:
  lookalike-character: strict
```

部首の字のほかに、互換漢字、濁点が別の字に分かれた「か゛」、カタカナの間の全角ハイフン（ニュ－ス）も同じように指します。コードの中も見ます。
濁点や部首のように、字そのものを話題にして例を見せている所は指しません。

```text chaff-explain
$ npx chaffjs explain lookalike-character --genre business/report

  見た目が同じで別の字   (lookalike-character)

  部首の字（⼈ U+2F08）や互換漢字は、ふつうの「人」と同じに見えて別の字です。濁点を別の字にした「か＋゛」（macOS のファイル名や、そこからコピーした文に多い）も、「が」と同じに見えて別の並びです。カタカナの間の全角ハイフン「－」やマイナス「−」（ニュ－ス）も、長音の「ー」に見えて別の字です。どれも検索、並べ替え、辞書引き、表記の照合から漏れ、読み手には直す所が見えません。PDF からのコピーや、入力の変換で入ります。コードの中も見ます。

  直しかた: その字を消して、ふつうの字を打ち直してください。文書全体を NFC に正規化しても直ります（部首の字は NFKC）。

  書き直しの深さ: light（語と文を直す。構成と文体は残す）。chaff fix-plan --depth でこれより浅い深さを選ぶと、計画はこのルールを直さず、名前だけを挙げます。

  設定できる値（数える上限は無く、指摘の重さが変わります）:
    strict   エラー
  → normal   注意
    relaxed  参考
    off      見ない

  いまは normal です。

  変える:  npx chaffjs relax lookalike-character --why "理由"
```

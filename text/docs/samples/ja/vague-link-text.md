# 行き先を言わないリンクの言葉（`vague-link-text`）

**こんな文書に:** 社内のお知らせ、ウェブに載せる案内、メールの本文。リンクを「こちら」とだけ書く形がよくあります。

## 元の文章

```markdown chaff-before
# 年末調整の書類の提出について

今年の年末調整の書類を、11月28日までに人事部へ出してください。

書類の書式は[こちら](https://example.com/nencho/shoshiki)からダウンロードできます。記入のしかたが分からないときは、[こちら](https://example.com/nencho/kinyurei)の記入例を見てください。

保険料の控除の証明書も、書類と一緒に11月28日までに提出してください。
```

## 直した文章

```markdown chaff-after
# 年末調整の書類の提出について

今年の年末調整の書類を、11月28日までに人事部へ出してください。

[年末調整の書類の書式](https://example.com/nencho/shoshiki)をダウンロードして使ってください。記入のしかたが分からないときは、[書類の記入例](https://example.com/nencho/kinyurei)を見てください。

保険料の控除の証明書も、書類と一緒に11月28日までに提出してください。
```

## 直し方

このお知らせには、リンクが二つあり、どちらも「こちら」と書いてあります。
リンクの前後の文を読み直さないと、どちらが書式で、どちらが記入例なのか分かりません。
画面の読み上げはリンクだけを並べて読むことがあり、そのときは「こちら、こちら」と聞こえるだけです。

直した文章では、行き先の名前をリンクの言葉にしました。
「書類の書式」「書類の記入例」と、リンクだけを拾い読みしても行き先が分かります。

## 設定

この規則は、指摘の重さだけが変わります。ふだんは「注意」として出し、`strict` で「エラー」、`relaxed` で「参考」になります。

```yaml chaff-settings
rules:
  vague-link-text: relaxed
```

リンクの言葉全体が「こちら」「ここ」「詳細」のような語のときだけ指します。言葉の一部に「こちら」を含むだけのリンク（「料金表はこちら」）は、行き先を言っているので指しません。
URL をそのまま書いたリンク、参照の形のリンク（[こちら][1]）、引用とコードの中のリンクも見ません。
Markdown の文書でだけ動きます。どのジャンルでも動きます。

```text chaff-explain
$ npx chaffjs explain vague-link-text --genre business/report

  行き先を言わないリンクの言葉   (vague-link-text)

  「[こちら](…)」「[ここをクリック](…)」のように、リンクの言葉がそれだけでは行き先を言わないと、読み手はリンクの前後を読み直して行き先を推し量ることになります。画面読み上げはリンクだけを並べて読み上げるので、「こちら、こちら、こちら」と聞こえ、どれがどこへ行くのか分かりません（WCAG 2.4.4 リンクの目的）。言葉全体が語彙表の語（こちら、ここ、詳細、click here、read more）のときだけを指し、行き先を言っている言葉（「料金表はこちら」）は指しません。

  直しかた: 行き先の名前をリンクの言葉にしてください（「料金は[こちら](…)」→「[料金表](…)を見てください」）。

  設定できる値（数える上限は無く、指摘の重さが変わります）:
    strict   エラー
  → normal   注意
    relaxed  参考
    off      見ない

  いまは normal です。

  変える:  npx chaffjs relax vague-link-text --why "理由"
```

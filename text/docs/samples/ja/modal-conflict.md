# 同じ行為への逆の決まり（`modal-conflict`）

**こんな文書に:** 契約書、利用規約、社内規程。別のひな形から条を写してきたときに、同じ行為を一方では禁じ、もう一方では認めてしまう形がよくあります。

## 元の文章

```markdown chaff-before
# システム保守業務委託契約書

株式会社みなと物流（以下「委託者」という。）と株式会社ほしぞらシステム（以下「受託者」という。）は、配送管理システムの保守について、次のとおり契約を結ぶ。

## 第1条（業務の内容）

受託者は、配送管理システムの障害の調査と修正を行う。

## 第2条（再委託の禁止）

受託者は、本件業務を第三者に委託してはならない。

## 第3条（報告）

受託者は、毎月の作業の結果を、翌月の5日までに委託者に報告する。

## 第4条（作業の体制）

受託者は、本件業務を第三者に委託することができる。この場合、受託者は、その第三者の作業について責任を負う。
```

## 直した文章

```markdown chaff-after
# システム保守業務委託契約書

株式会社みなと物流（以下「委託者」という。）と株式会社ほしぞらシステム（以下「受託者」という。）は、配送管理システムの保守について、次のとおり契約を結ぶ。

## 第1条（業務の内容）

受託者は、配送管理システムの障害の調査と修正を行う。

## 第2条（再委託の禁止）

受託者は、委託者の書面による承諾を得た場合を除き、本件業務を第三者に委託してはならない。

## 第3条（報告）

受託者は、毎月の作業の結果を、翌月の5日までに委託者に報告する。

## 第4条（作業の体制）

受託者が第2条の承諾を得て本件業務を第三者に委託したときは、受託者は、その第三者の作業について責任を負う。
```

## 直し方

第2条は「本件業務を第三者に委託してはならない」と禁じています。
ところが第4条は、同じ行為を「第三者に委託することができる」と認めています。
受託者は、下請けに出してよいのか悪いのか、この契約書からは決められません。
もめたときには、どちらの条を当てはめるかで争いになります。第4条だけを、別の契約のひな形から写してきた、という形です。

直した文章では、再委託は委託者の書面による承諾があるときだけ認める、と決めました。
第2条に承諾という例外を書き足し、第4条は、承諾を得て委託したときの責任の条に書き直しています。
どちらの決まりを残すかは、当事者が決めることです。chaff は、逆の決まりが並んでいる所を示すだけです。

## 設定

この規則は、指摘の重さだけが変わります。ふだんは「注意」として出し、`strict` で「エラー」、`relaxed` で「参考」になります。

```yaml chaff-settings
rules:
  modal-conflict: strict
```

主語と中身の語（名詞・動詞・形容詞）がまったく同じ二つの文だけを比べます。条件や例外を書き分けていれば、中身の語が違うので指摘しません。
「しなければならない」と「することができる」は、食い違いとは見ません。
どのジャンルでも動きます。

```text chaff-explain
$ npx chaffjs explain modal-conflict --genre legal/contract

  同じ行為への逆の決まり   (modal-conflict)

  同じ人の同じ行為を、ある文では「しなければならない」「することができる」と、別の文では「してはならない」と書くと、読み手はどちらに従えばよいか分かりません。後から足した条や、別の文書から写した文で起きます。条件や例外を書き分けていれば、二つの文の中身の語が違うので、ここには出ません。

  直しかた: どちらが正しいかを決め、もう一方を消すか、条件や例外（「書面で承諾を得た場合を除き」）を書き足して二つの範囲を分けてください。

  書き直しの深さ: light（語と文を直す。構成と文体は残す）。chaff fix-plan --depth でこれより浅い深さを選ぶと、計画はこのルールを直さず、名前だけを挙げます。

  設定できる値（数える上限は無く、指摘の重さが変わります）:
    strict   エラー
  → normal   注意
    relaxed  参考
    off      見ない

  いまは normal です。

  変える:  npx chaffjs relax modal-conflict --why "理由"
```

# 必須の条件を歓迎の条件にも挙げている（`required-listed-as-preferred`）

**こんな文書に:** 求人票、募集の要項、委託先を選ぶ条件の一覧。前の求人を写して条件を書き換えたときに、同じ項目が「必須」と「歓迎」の両方に残る形がよくあります。

## 元の文章

```markdown chaff-before
# 募集：店舗の運営スタッフ（正社員）

駅前のベーカリーカフェで、売場と厨房の両方を受け持つスタッフを募集します。

## 応募資格（必須）

- 飲食店での接客の経験が1年以上あること
- 食品衛生責任者の資格をお持ちの方
- 土日に勤務できる方
- 朝6時からの勤務ができる方

## 歓迎条件

- 食品衛生責任者の資格をお持ちの方
- パンや菓子の製造の経験
```

## 直した文章

```markdown chaff-after
# 募集：店舗の運営スタッフ（正社員）

駅前のベーカリーカフェで、売場と厨房の両方を受け持つスタッフを募集します。

## 応募資格（必須）

- 飲食店での接客の経験が1年以上あること
- 土日に勤務できる方
- 朝6時からの勤務ができる方

## 歓迎条件

- 食品衛生責任者の資格をお持ちの方
- パンや菓子の製造の経験
```

## 直し方

この求人では、「食品衛生責任者の資格」が、必須の応募資格にも、歓迎する資格にも挙がっています。
読む人には、この資格が無いと応募できないのか、あれば有利になるだけなのかが分かりません。
資格を持っていない人の中には、本当は応募してほしかった人まで、あきらめてしまう人が出ます。
前の募集を写したときに、必須から歓迎へ移したつもりで、元の行を消し忘れた形です。

直した文章では、入社後に取ってもらえばよい資格として、必須から消し、歓迎だけに残しました。
必ず要る資格なら、反対に歓迎から消します。歓迎のほうで上の水準を求めるなら、「接客の経験が3年以上」のように、違いを書きます。

## 設定

この規則は、指摘の重さだけが変わります。ふだんは「注意」として出し、`strict` で「エラー」、`relaxed` で「参考」になります。

```yaml chaff-settings
rules:
  required-listed-as-preferred: strict
```

必須（必須スキル、応募資格）と歓迎（歓迎スキル、尚可）の見出しや札の下の箇条書きを比べ、同じ項目が両方にあれば歓迎のほうを指します。項目の終わりの「の方」「こと」と、経験の長さ（3年以上）は外して比べます。
歓迎のほうが長い経験を求める項目、違う言葉で同じことを言う項目（「簿記2級」と「日商簿記2級」）、資格の級の違いは指しません。
文学（`literature`）のジャンルでは動きません。

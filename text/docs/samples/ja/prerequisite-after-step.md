# 手順の後に書いた前提（`prerequisite-after-step`）

**こんな文書に:** 操作マニュアル、作業の手順書、社内の手引き。手順を書き終えてから大事な注意を思い出し、手順の下に書き足す形がよくあります。

## 元の文章

```markdown chaff-before
# 売上のデータを新しいパソコンに移す

会計ソフトの入ったパソコンを買い替えたときに、経理の担当が行います。

## 手順

1. 古いパソコンで会計ソフトを開き、「データの書き出し」を選びます。
2. 書き出したファイルを、USBメモリに保存します。
3. 新しいパソコンで会計ソフトを開き、「データの読み込み」からそのファイルを選びます。

作業を始める前に、古いパソコンの会計ソフトで、その日の売上の入力を済ませておきます。
```

## 直した文章

```markdown chaff-after
# 売上のデータを新しいパソコンに移す

会計ソフトの入ったパソコンを買い替えたときに、経理の担当が行います。

## 手順

作業を始める前に、古いパソコンの会計ソフトで、その日の売上の入力を済ませておきます。

1. 古いパソコンで会計ソフトを開き、「データの書き出し」を選びます。
2. 書き出したファイルを、USBメモリに保存します。
3. 新しいパソコンで会計ソフトを開き、「データの読み込み」からそのファイルを選びます。
```

## 直し方

この手引きは、データを移す三つの手順の後に、「作業を始める前に、その日の売上の入力を済ませておきます。」と書いています。
手引きを上から順に読む人は、この文を読むころには、もう手順3まで終えています。
入力が済んでいない売上は、新しいパソコンに移らないまま残ってしまいます。

直した文章では、この一文を手順のすぐ上に移しました。
前提や準備、要る権限は、手順の前に書きます。前提がいくつもあるなら、「始める前に」という節を手順の前に立てるのもよい書き方です。

## 設定

この規則は、指摘の重さだけが変わります。ふだんは「参考」として出し、`strict` にすると「注意」になります。

```yaml chaff-settings
rules:
  prerequisite-after-step: strict
```

番号付きの手順が三つ以上ある節で、その手順より後に「作業を始める前に」「始める前に」で始まる文があるときだけ指します。
手順の前にある前提や、「手順4の前に」のように一つの手順を名指す文は指しません。
技術文書、手順書、ブログのジャンルで動き、法令や契約（`legal`）、論文（`academic`）、文学（`literature`）、話し言葉（`speech`）では動きません。

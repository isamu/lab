# 定義した語を、定義と違う形で使っている（`defined-term-form`）

**こんな文書に:** 利用規約、契約書、社内の規程。条文を足したり、ほかの規約から写したりすると、定義した語にかぎ括弧が付いたままになったり、「本」が「本件」に変わったりします。

## 元の文章

```markdown chaff-before
# 会員サービス利用規約

## 第1条（定義）

当社は、料理教室の予約と動画の配信を行うサービス（以下「本サービス」という。）を会員に提供する。

## 第2条（会員の登録）

本サービスを使う者は、当社の定める方法で会員の登録をする。

## 第3条（禁止する行為）

会員は、「本サービス」で配信する動画を、当社の許しなく他人に見せてはならない。

## 第4条（停止）

当社は、設備の点検のため、本サービスを一時止めることがある。
```

## 直した文章

```markdown chaff-after
# 会員サービス利用規約

## 第1条（定義）

当社は、料理教室の予約と動画の配信を行うサービス（以下「本サービス」という。）を会員に提供する。

## 第2条（会員の登録）

## 第3条（禁止する行為）

会員は、本サービスで配信する動画を、当社の許しなく他人に見せてはならない。

## 第4条（停止）

```

## 直し方

第1条で「本サービス」と定義したあと、第3条だけかぎ括弧を付けて「「本サービス」」と書いています。
規約でかぎ括弧に入れるのは、ふつう語を新しく定めるときです。読み手は、ここで別の意味に定め直したのか、第1条と同じものなのかが分かりません。

定義した語は、定義した形のまま使います。第3条のかぎ括弧を外して、ほかの条と同じ「本サービス」にしました。
「本サービス」を「本件サービス」と書き換えた所や、「動画配信本サービス」のように語を足して長くした所も、chaff は同じように指します。

## 設定

```yaml chaff-settings
rules:
  defined-term-form: strict
```

設定の値は、英語の契約で、大文字で定義した語を小文字で書いた所を何個まで指摘するかを決めます。
小文字の使い方が多いときは、ふつうの意味で使っていると読んで指しません。日本語のかぎ括弧や「本」と「本件」の入れ替えは、どの値でも指摘します。見たくなければ `off` にします。
法務のジャンル（`legal/*`）でだけ動きます。説明書や論文、文芸、講演のジャンルでは、はじめから動きません。

# 戻り値の型が二通りに書かれている（`return-type-mismatch`）

**こんな文書に:** ライブラリの README、API リファレンス、社内ツールの説明。戻り値を変えたときに、シグネチャか説明の片方だけを直すと、二通りの型が残ります。

## 元の文章

````markdown chaff-before
# textwidth

画面に出したときの文字列の幅を測る、小さなライブラリです。

## measure

```ts
measure(text: string, tabSize = 4): number
```

measure は、幅を "12" のような文字列で返します。
全角の文字は2、半角の文字は1と数えます。タブは tabSize の幅まで広げて数えます。
````

## 直した文章

````markdown chaff-after
# textwidth

画面に出したときの文字列の幅を測る、小さなライブラリです。

## measure

```ts
measure(text: string, tabSize = 4): number
```

measure は、幅を桁数の数値で返します。
全角の文字は2、半角の文字は1と数えます。タブは tabSize の幅まで広げて数えます。
````

## 直し方

シグネチャでは measure の戻り値は number ですが、説明の文は「文字列で返します」と言っています。
読み手はどちらを信じてよいか分かりません。説明を信じて文字列として扱うと、足し算が文字のつなぎになるような、見つけにくい不具合になります。

実際のコードを確かめると number を返していたので、説明の文を「数値で返します」に直しました。
chaff は、コードブロックのシグネチャを基準に、同じ見出しの下の「戻り値：」の行、戻り値の列を持つ表、関数名を主語にして「返します」と言う文を比べます。「文字列」「数値」のような語は、型の種類として比べます。

## 設定

ふだんは「注意」として出します。`strict` にすると「エラー」、`relaxed` にすると「参考」になります。

```yaml chaff-settings
rules:
  return-type-mismatch: strict
```

`Array<string>` と `string[]` のような同じ型の別の書き方は、同じと読みます。async の宣言の `Promise<T>` は `T` として比べます。
シグネチャの無い関数、オーバーロード（どちらかに合えば合っていると見ます）、オブジェクトの型、ユニオンの一部だけを言う説明、「返していました」「返しません」のような過去や否定の文は見ません。
技術の文書、手順書、記事で動きます。契約や法令、論文、文芸では、はじめから動きません。

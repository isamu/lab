# 見出しの無い目次の項目（`toc-heading-mismatch`）

**こんな文書に:** 報告書、仕様書、社内の手引き。本文の見出しを書き換えたり節を消したりしたあとに、目次だけが古いまま残る形がよくあります。

## 元の文章

```markdown chaff-before
# 倉庫の在庫管理の見直し 報告書

## 目次

- 1. 見直しの目的
- 2. 今の在庫の数え方
- 3. 新しいバーコードの読み取り機
- 4. これからの予定

## 1. 見直しの目的

棚卸しのたびに数が合わず、毎回の数え直しに半日かかっていたため、在庫の数え方を見直しました。

## 2. 今の在庫の数え方

今は、月末に2人1組で棚を回り、紙の一覧に数を書いています。

## 3. 読み取り機の試し使い

9月の2週間、第2倉庫で手持ちの読み取り機を試しに使いました。棚卸しにかかる時間は、半日から2時間に縮みました。

## 4. これからの予定

来年の1月から、すべての倉庫で読み取り機を使います。
```

## 直し方

目次の三つ目は「新しいバーコードの読み取り機」ですが、本文の3章の見出しは「読み取り機の試し使い」です。
試し使いの結果を書き足したときに、見出しを書き換え、目次を直し忘れた形です。
目次を頼りに読む人は、「新しいバーコードの読み取り機」という見出しを探して、見つけられません。
報告を受ける人がまず知りたい試し使いの結果が、目次からは見えなくなっています。

直した文章では、目次の項目を、今の見出し「読み取り機の試し使い」に合わせました。
節を消したのなら、目次からもその項目を消します。

## 設定

この規則は、指摘の重さだけが変わります。ふだんは「注意」として出し、`relaxed` にすると「参考」になります。

```yaml chaff-settings
rules:
  toc-heading-mismatch: relaxed
```

目次の項目と見出しは、空白・記号・大文字と小文字の違いを無視し、頭の番号（1.2、2-1）とページ番号（…… 12）を外しても比べます。
目次の項目の半分より多くが見出しに合わない文書は、本文と別の章立ての目次と読んで指摘しません。
「目次」「Contents」の見出しの下の箇条書きを目次と読みます。どのジャンルでも動きます。

```text chaff-explain
$ npx chaffjs explain toc-heading-mismatch --genre business/report

  直しかた: 目次を見出しに合わせて直すか、消えた節の項目を目次から消してください。

  設定できる値（数える上限は無く、指摘の重さが変わります）:
  → normal   注意
    relaxed  参考
    off      見ない

  変える:  npx chaffjs relax toc-heading-mismatch --why "理由"
```

# 定義より前で使っている語（`use-before-definition`）

**こんな文書に:** 契約書、覚書、利用規約。下書きの頭に一文を書き足したときに、まだ定義していない「委託者」「受託者」を先に使ってしまう形がよくあります。

## 元の文章

```markdown chaff-before
# 店舗清掃業務委託契約書

この契約は、受託者が委託者の店舗で行う清掃の業務について定める。株式会社ひだまり商店（以下「委託者」という。）と有限会社みずほクリーン（以下「受託者」という。）は、次のとおり契約を結ぶ。

## 第1条（業務の内容）

受託者は、委託者の店舗の床、窓及び手洗い場を、毎週月曜日と木曜日に清掃する。

## 第2条（委託料）

委託者は、毎月の委託料を、翌月の10日までに受託者の指定する口座に振り込む。
```

## 直した文章

```markdown chaff-after
# 店舗清掃業務委託契約書

株式会社ひだまり商店（以下「委託者」という。）と有限会社みずほクリーン（以下「受託者」という。）は、受託者が委託者の店舗で行う清掃の業務について、次のとおり契約を結ぶ。

## 第1条（業務の内容）

受託者は、委託者の店舗の床、窓及び手洗い場を、毎週月曜日と木曜日に清掃する。

## 第2条（委託料）

委託者は、毎月の委託料を、翌月の10日までに受託者の指定する口座に振り込む。
```

## 直し方

この契約書の最初の文は「受託者が委託者の店舗で行う清掃」と、いきなり「受託者」「委託者」を使っています。
ところが、どちらがどの会社かを決めているのは、その次の文です。
読む人は、誰のことか分からない語を先に読み、次の文まで来てから意味を知ります。
こうなるのは、定義を書いたあとで、その前に説明の一文を書き足したときが多いです。

直した文章では、書き足した一文を定義の文にまとめ、委託者と受託者を決めてから使うようにしました。
定義を最初に使う所へ移すか、定義より前の所を定義した語を使わない書き方にすれば直ります。

## 設定

この規則は、指摘の重さだけが変わります。ふだんは「参考」として出し、`strict` にすると「注意」になります。

```yaml chaff-settings
rules:
  use-before-definition: strict
```

文の途中で括弧に入れて定義した語（以下「委託者」という。）だけを見ます。「甲」「乙」のような一字の語は、ほかの語の一部と見分けられないので見ません。
定義の条（「X」とは…をいう）で定義した語は、定義の条を文書の終わりに置く書き方もあるので、前で使っても言いません。
見出しの行の語と、目次の項目は、使った所に数えません。前で使った最初の一か所だけを指します。
どのジャンルでも動きます。

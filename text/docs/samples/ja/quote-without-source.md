# 人の言葉として引いた文に出典がない（`quote-without-source`）

**こんな文書に:** 技術ブログ、エッセイ、論文。覚えている言葉を書き留めたまま、誰がどこで言ったのかを書かない形がよくあります。

## 元の文章

```markdown chaff-before
# レビューを小さく分ける

先月から、チームで一つの変更を小さく分けて出すようにした。

ある先輩エンジニアは「指摘が十を超えるレビューは、たいてい変更の分け方がまずい」と書いている。
読み返すと、私たちのレビューもそうだった。大きな変更ほど指摘が増え、直すたびに新しい指摘が出ていた。

いまは、一つの変更を一つの目的に絞っている。レビューは一日で終わることが増えた。
```

## 直した文章

```markdown chaff-after
# レビューを小さく分ける

先月から、チームで一つの変更を小さく分けて出すようにした。

ある先輩エンジニアは「指摘が十を超えるレビューは、たいてい変更の分け方がまずい」と書いている[^1]。
読み返すと、私たちのレビューもそうだった。大きな変更ほど指摘が増え、直すたびに新しい指摘が出ていた。

いまは、一つの変更を一つの目的に絞っている。レビューは一日で終わることが増えた。

[^1]: 社内勉強会の資料「レビューを速くする」（2025年）より。
```

## 直し方

鉤括弧の中を、先輩エンジニアの言葉として引いています。けれども、どこに書かれていたのかがありません。
読み手は、その人が本当にそう書いたのか、言い回しが正しいのかを確かめられません。人から人へ伝わるうちに、言葉や言った人が入れ替わるのは、引用でいちばんよく起きる誤りです。

直した文章では、脚注で出典を書きました。Web で読めるものならリンクを、本や論文なら著者と書名と年を書きます。
出典が見つからないなら、言い回しを確かめられるまで、人の言葉としては引かないようにします。
`npx chaffjs cite --scaffold post.md` は、こうした引用を照らし合わせるためのひな形を作ります。出典のファイルを書いて `chaff cite` を動かすと、その言葉が出典に本当にあるかを照らせます。

## 設定

ふだんは「参考」として出します。`strict` にすると「注意」になります。

```yaml chaff-settings
rules:
  quote-without-source: strict
```

同じ段落か、空行をはさまずに続く行に、リンク、URL、脚注、番号の引用（[3]）、括弧の中の年があれば、出典を書いたと見ます。
「保存」ボタンのような短い鉤括弧や、誰かに帰する言い回し（と述べた、によれば）の無い引用は見ません。
記事と論文で動きます。組織の記事、プレスリリース、手順書、契約や法令、小説、話し言葉では、はじめから動きません。

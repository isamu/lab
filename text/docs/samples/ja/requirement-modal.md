# 規定の文末が、決めた書き方と違う（`requirement-modal`）

**こんな文書に:** 社内規程、作業の基準、仕様書、試験の手順。守るべきことと、望ましいだけのことを書き分ける文書です。

## 元の文章

```markdown chaff-before
# 業務データのバックアップの基準

## 1 バックアップの取得

各部署は、業務データのバックアップを毎日取得しなければならない。
バックアップは、社外のデータセンターにも保管すべきである。

## 2 復元

情報システム課は、申請を受けて、7日前までのデータを復元できる。
```

```yaml chaff-config
options:
  requirement-modal:
    standard: jis-z8301-2019
```

## 直した文章

```markdown chaff-after
# 業務データのバックアップの基準

## 1 バックアップの取得

各部署は、業務データのバックアップを毎日取得しなければならない。
バックアップは、社外のデータセンターにも保管することが望ましい。

## 2 復元

情報システム課への申請により、7日前までのデータを復元することが可能である。
```

## 直し方

この会社の規程は、JIS Z 8301:2019 の書き分けに合わせると決めています。守らなければならないことは「しなければならない」、望ましいだけのことは「することが望ましい」、してもよいことは「してもよい」と書きます。
「保管すべきである」は、読む人によって「必ず保管する」とも「できれば保管する」とも取れます。監査のときに、守っていないのか、守らなくてよかったのかで話が分かれます。
「復元できる」も、情報システム課に許していることなのか、仕組みとして戻せることなのかが分かりません。

直した文章では、社外での保管を「望ましい」こととし、復元は仕組みとして戻せる範囲を書く「可能である」にしました。
1 条の「取得しなければならない」は、もともと決まりどおりの要求の形なので、そのままです。

## 設定

この規則は、何を見るかを chaff.yaml の `options` で選んだときだけ動きます。選ばなければ何も見ません。
文末の決まりはチームが選ぶものだからです。JIS Z 8301:2019 の決まりで見るなら、こう書きます。

```yaml chaff-settings
options:
  requirement-modal:
    standard: jis-z8301-2019
```

文書の書き方を JIS Z 8301:2019 にそろえる `style` を選んでも、この見方が入ります。

```yaml chaff-settings
style: jis-z8301-2019
```

指すのは、文の終わりの「すべきである」「すべきでない」「できる」「できない」です。
「直すことができる場合は」のように、文の途中で能力を言う「できる」は指摘しません（JIS もこの使い方は認めています）。
ふだんは「注意」、`strict` で「エラー」、`relaxed` で「参考」になります。

```yaml chaff-settings
rules:
  requirement-modal: strict
```

英語の文書では、同じ `options` の `shall: must` で、"shall" を "must" に直すよう指摘します。

# 同じ略語の二通りの展開（`acronym-expansion-conflict`）

**こんな文書に:** 設計書、運用の手順書、社内の報告書。別の資料から段落を写したときや、AI に下書きを頼んだときに、同じ略語が二つの意味で書かれていることがあります。

## 元の文章

```markdown chaff-before
# 受注システムのバックアップ方針

## 目標

受注システムの RPO（目標復旧時点）は1時間とします。
障害が起きても、失うデータを直前1時間分までに抑えるという意味です。

## 方式

データベースは1時間ごとに差分を取り、毎晩0時に全体を別の拠点へ写します。
写した控えは30日分を残し、それより古いものは自動で消します。

## 見直し

半年に一度、実際に控えから戻す訓練をします。
戻すのにかかった時間が長すぎるときは、RPO（復旧優先度）の高い業務から順に戻せるよう、手順を組み直します。
```

## 直した文章

```markdown chaff-after
# 受注システムのバックアップ方針

## 目標

受注システムの RPO（目標復旧時点）は1時間とします。
障害が起きても、失うデータを直前1時間分までに抑えるという意味です。

## 方式

データベースは1時間ごとに差分を取り、毎晩0時に全体を別の拠点へ写します。
写した控えは30日分を残し、それより古いものは自動で消します。

## 見直し

半年に一度、実際に控えから戻す訓練をします。
戻すのにかかった時間が長すぎるときは、復旧の優先度が高い業務から順に戻せるよう、手順を組み直します。
```

## 直し方

この方針では、RPO を初めに「目標復旧時点」と書き、最後の段落では「復旧優先度」と書いています。
読み手は、同じ RPO の話なのか、別の指標が出てきたのかが分かりません。障害の最中にこの文書を開いた人が、どちらの意味で読めばよいかで迷うのは困ります。

最後の段落で言いたいのは、どの業務から先に戻すかという順番で、目標復旧時点のことではありません。
そこで、略語を使わずに「復旧の優先度」と言葉で書きました。RPO は一つの意味だけで使われるようになります。
二つが同じものを指していたのなら、二度目は「RPO」とだけ書けば足ります。

## 設定

```yaml chaff-settings
rules:
  acronym-expansion-conflict: relaxed
```

指摘の重さを変えるだけで、見つける所は変わりません。
`strict` にするとまちがいとして、`relaxed` にすると参考として出します。見たくなければ `off` にします。
どのジャンルでも動きます。

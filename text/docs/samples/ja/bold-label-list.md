# 太字の札で始まる箇条書きが多い（`bold-label-list`）

**こんな文書に:** 比べた記録、選定の報告、ブログ。AI に「分かりやすくまとめて」と頼むと、「- **重さ**：〜」の形の箇条書きが並びます。

## 元の文章

```markdown chaff-before
# 営業部のノートパソコンを選び直した

営業部で使っているノートパソコンが五年目に入り、電池が半日もたなくなってきました。
今年の秋に十台を入れ替えます。
候補を三機種まで絞って、二週間ずつ試しました。
決めるときに見たことを、次の人のために残しておきます。

- **重さ**：毎日持ち歩くので、1.2キロを超えるものは外しました。
- **電池**：外回りの日に充電なしで夕方までもつかを、実際に使って確かめました。
- **画面**：お客さまに見せることが多いので、明るい屋外でも読めるかを見ました。
- **端子**：会議室のプロジェクターにつなぐ端子が、変換なしで挿せるものにしました。
- **価格**：一台あたり十五万円の予算に収まるかを確かめました。
- **保守**：壊れたときに、三日以内に代わりの機械が届く契約があるかを見ました。

最後まで迷ったのは、二つの機種でした。
片方は軽くて電池も長くもちましたが、画面が暗く、屋外では資料が読みにくかったです。
もう片方は少し重いものの、画面が明るく、端子も揃っていました。
営業の六人に使ってもらうと、五人が後者を選びました。
決め手は画面です。
重さの差は二百グラムで、持ち歩いても気にならないという声がほとんどでした。
```

# 営業部のノートパソコンを選び直した

営業部で使っているノートパソコンが五年目に入り、電池が半日もたなくなってきました。
今年の秋に十台を入れ替えます。

## 直し方

元の文章は、選ぶときに見たことを「**重さ**」「**電池**」「**画面**」と、太字の札を付けた六つの項目に分けています。
札が並ぶと、どの項目も同じ重さの見出しに見えます。
実際には、重さと価格と保守は候補を絞る条件で、決め手になったのは画面でした。
その違いが、箇条書きでは書かれません。

直した文章では、札を外して、項目を文にしました。
候補を絞った条件（重さ、価格、保守、端子）を一つの段落にまとめ、試しで見た二つ（電池と画面）を次の段落に分けています。
こうすると、続く「決め手は画面です」が、どこから来たのか読み手に分かります。

## 設定

太字の札で始まる項目が5個あると指摘します。

```yaml chaff-settings
rules:
  bold-label-list: relaxed
```

`relaxed` にすると8個から、`strict` なら3個からです。
「- **情報が古くなる。** 〜」のように太字の一文で始まる項目は、3個から指摘します。この数は `options` の `min_leads` で変えられます。

```yaml chaff-settings
options:
  bold-label-list:
    min_leads: 5
```

札がコードだけの項目（`--flag` の説明）と、一項目ずつ段落ほどの長さがある箇条書きは数えません。
用語集のように、本当に札と説明の組を並べるものは、そのままでかまいません。
法令・契約（`legal`）、手順書（`docs`）、論文（`academic`）、文学（`literature`）、議事録（`business/meeting-notes`）、講演の書き起こし（`speech/transcript`）のジャンルでは、はじめから動きません。

このルールは AI らしさの目安にも数えます。文章全体の目安は `npx chaffjs ai-score post.md` で見られます。

```text chaff-explain
$ npx chaffjs explain bold-label-list --genre blog/tech

  太字の札で始まる箇条書きが多い   (bold-label-list)

  「- **速さ**：〜」のように、項目ごとに太字の札とコロンを置いて説明を続ける形です。「- **情報が古くなる。** 〜」のように、太字の一文で始めて説明を続ける形も同じです。札が並ぶと、どの項目も同じ重さの見出しに見え、項目どうしの繋がりは書かれません。段落ごとに「**利用は毎週伸びた**：〜」と、言い切りの太字で始めて説明を続ける形も同じです。生成文によく見られる形です。

  直しかた: 札を外して、項目を文にしてください。大事な項目が 1 つ 2 つなら、それを段落で書き、残りは消すか 1 文にまとめます。用語集のように、本当に札と説明の組を並べるものはそのままでかまいません。

  書き直しの深さ: structure（節・見出し・段落を組み替える）。chaff fix-plan --depth でこれより浅い深さを選ぶと、計画はこのルールを直さず、名前だけを挙げます。

  設定できる値:
    strict   太字の札で始まる項目が 3 個あれば指摘（太字の一文で始まる項目は min_leads、言い切りの太字で始まる段落は min_clause_paragraphs の数から）
  → normal   太字の札で始まる項目が 5 個あれば指摘（太字の一文で始まる項目は min_leads、言い切りの太字で始まる段落は min_clause_paragraphs の数から）
    relaxed  太字の札で始まる項目が 8 個あれば指摘（太字の一文で始まる項目は min_leads、言い切りの太字で始まる段落は min_clause_paragraphs の数から）
    off      見ない

  オプション（chaff.yaml の options で決めます）:
    min_leads: 3   （既定）
      太字の一文で始まる項目（- **範囲を固定する。** 〜）だけで指摘する数。人の文書は手順や欄の名前に太字の札を 3 つ 4 つ並べることはあっても、太字の一文で始まる項目を並べることはほとんどありません。得られることを言う札（- **作業時間の削減**：〜、語彙表 benefit-label の語で終わるもの）も、手順や欄の名前ではなく言い分なので、一緒に数えます
    min_clause_paragraphs: 3   （既定）
      言い切りの太字（述語のある文。**利用は毎週伸びた**：〜）で始まる段落だけで指摘する数。句点で閉じた英語の命令の一文（**Pick the quietest room you can.** 〜）も数えます。人の文書の段落の頭の太字は、語だけのもの（**勤務時間**：）、コロンで閉じた動詞で始まるもの（英語の命令形 **Talk to the people:**）、動名詞（**Examining the risks.**）、問い（**読み手は誰か？**）がほとんどで、これらは数えません。品詞が読めないときは段落を数えません

  決める:  chaff.yaml に options: { bold-label-list: { <名前>: <値> } } を書く

  いまは normal です。

  変える:  npx chaffjs relax bold-label-list --why "理由"
```

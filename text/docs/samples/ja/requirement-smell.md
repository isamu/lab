# 要求の文に、決めきれない言い方がある（`requirement-smell`）

**こんな文書に:** 要求仕様書、設計書、発注の仕様、契約書。作る人と頼む人が別のとき、「可能な限り」「等」が、後で揉める種になります。

## 元の文章

```markdown chaff-before
# 会議室予約システム 要求仕様

## 1. 目的

社員が、空いている会議室を自分の席から探して予約できるようにする。

## 2. 機能の要求

2.1 予約の一覧の画面は、可能な限り速く表示されなければならない。

2.2 予約を取り消したときは、予約した人に、取り消しを知らせるメールを送ること。

2.3 予約の記録には、予約した人、会議室、日時等を保存すること。

2.4 管理者は、会議室ごとに、予約できる時間帯を決められること。

## 3. 前提

会議室は、本社の3階と5階にある十二室とする。
```

## 直した文章

```markdown chaff-after
# 会議室予約システム 要求仕様

## 1. 目的

社員が、空いている会議室を自分の席から探して予約できるようにする。

## 2. 機能の要求

2.1 予約の一覧の画面は、開く操作から2秒以内に表示されなければならない。

2.2 予約を取り消したときは、予約した人に、取り消しを知らせるメールを送ること。

2.3 予約の記録には、予約した人、会議室、開始と終了の日時、予約した日時の四つを保存すること。

2.4 管理者は、会議室ごとに、予約できる時間帯を決められること。

## 3. 前提

会議室は、本社の3階と5階にある十二室とする。
```

## 直し方

2.1 の「可能な限り速く」では、何秒で表示すれば要求を満たしたことになるのかが決まりません。作る側は「できる限りやった」と言え、頼んだ側は「遅い」と言えます。
2.3 の「日時等」は、ほかに何を保存するのかを残しています。作る側は書かれた三つだけを保存し、後から「取り消した日時も要る」と言われることになります。

直した文章では、2.1 を「開く操作から2秒以内に」と、測れる数で書きました。2.3 は「等」を外し、保存するものを四つ全部並べました。どちらも、出来上がったものを見て、満たしたかどうかを誰が読んでも同じに決められます。

## 設定

指摘の重さだけが変わります。ふだんは「参考」として出し、`strict` にすると「注意」になります。

```yaml chaff-settings
rules:
  requirement-smell: strict
```

要求の文（「〜しなければならない」「〜ものとする」「〜こと。」で終わる文）だけを見ます。説明や背景の文は見ません。
仕様書、契約書・規約、説明書で動きます。法令（`legal/statute`）は「等」を定義して使うので止めています。判決、特許、用語集、学術、文学、話し言葉でも止めています。
文書が定めた名前の「等」（以下「委託先等」という）は、一覧を閉じているので指しません。

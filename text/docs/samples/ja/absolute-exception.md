# 言い切った決まりに、別の所で例外がある（`absolute-exception`）

**こんな文書に:** 社内規程、就業規則、利用規約。言い切った条を先に書き、あとから例外の条を足したときに、元の条を直し忘れる形がよくあります。

## 元の文章

```markdown chaff-before
# 情報機器管理規程

## 第1条（目的）

この規程は、会社が貸与するパソコン等の情報機器の扱いを定める。

## 第2条（持出しの禁止）

従業員は、すべての業務用の端末を社外に持ち出してはならない。

## 第3条（保管）

従業員は、退社するときに、業務用の端末を鍵の掛かる棚に保管する。

## 第4条（出張の場合）

所属長が承認した出張に使う業務用の端末は、社外に持ち出してはならない端末から除く。
```

## 直した文章

```markdown chaff-after
# 情報機器管理規程

## 第1条（目的）

この規程は、会社が貸与するパソコン等の情報機器の扱いを定める。

## 第2条（持出しの禁止）

従業員は、第4条に定める場合を除き、業務用の端末を社外に持ち出してはならない。

## 第3条（保管）

従業員は、退社するときに、業務用の端末を鍵の掛かる棚に保管する。

## 第4条（出張の場合）

所属長が承認した出張に使う業務用の端末は、社外に持ち出してはならない端末から除く。
```

## 直し方

第2条は「すべての業務用の端末を社外に持ち出してはならない」と、例外なしに言い切っています。
ところが第4条には、承認を得た出張の端末は除く、と例外があります。
第2条だけを読んだ従業員は、出張にも端末を持って行けないと思い込みます。
反対に、第4条を知っている人は、第2条の「すべての」をどこまで信じてよいか分からなくなります。
あとから出張の条を足したときに、第2条を直し忘れた、という形です。

直した文章では、第2条に「第4条に定める場合を除き」と書き足し、「すべての」を消しました。
言い切った文を読んだだけで、例外があることと、その場所が分かります。
例外がもう要らないのなら、反対に第4条を消します。どちらにするかは書き手が決めることです。

## 設定

この規則は、指摘の重さだけが変わります。ふだんは「注意」として出し、`strict` で「エラー」、`relaxed` で「参考」になります。

```yaml chaff-settings
rules:
  absolute-exception: relaxed
```

例外を、言い切った文と同じ条や段落に書いたもの（ただし書）は、決まりの一部なので指摘しません。
言い切った文の中身の語を半分以上くり返さない例外は、別の行為の話と読んで見ません。
「しなければならない」「してはならない」のような義務の語の無い言い切りと、鉤括弧の中の語も見ません。
文学（`literature`）のジャンルでは動きません。

# 太字にならずに見える「**」（`unrendered-emphasis`）

**こんな文書に:** 操作マニュアル、社内の手引き、よくある質問。画面のボタンの名前を鉤括弧ごと太字にしたとき、日本語では太字にならずに記号が見えてしまう形がよくあります。

## 元の文章

```markdown chaff-before
# 勤怠の締め方

月末に、その月の勤怠を締める手順です。

## 手順

勤怠の画面を開き、その月の打刻に抜けが無いかを確かめます。抜けがあれば、日付を選んで時刻を入れ直します。

確かめ終わったら、**「月次締め」**ボタンを押してください。締めた後は、本人では打刻を直せなくなります。
```

## 直した文章

```markdown chaff-after
# 勤怠の締め方

月末に、その月の勤怠を締める手順です。

## 手順

勤怠の画面を開き、その月の打刻に抜けが無いかを確かめます。抜けがあれば、日付を選んで時刻を入れ直します。

確かめ終わったら、**「月次締め」ボタン**を押してください。締めた後は、本人では打刻を直せなくなります。
```

## 直し方

書いた人は、ボタンの名前を太字にしたつもりで「**「月次締め」**ボタン」と書きました。
ところが Markdown の決まりでは、閉じの「**」が鉤括弧のすぐ後ろにあり、その後ろに字が続くと、太字を閉じられません。
読む人の画面には、太字ではなく「**「月次締め」**ボタン」と、星の記号がそのまま出てしまいます。
一番目立たせたかった所が、一番読みにくくなります。

直した文章では、「**」で「「月次締め」ボタン」全体を囲み、閉じの記号を字のすぐ後ろに置きました。
鉤括弧があるだけで十分に目立つなら、太字をやめてもかまいません。

## 設定

この規則は、指摘の重さだけが変わります。ふだんは「注意」として出し、`strict` で「エラー」、`relaxed` で「参考」になります。

```yaml chaff-settings
rules:
  unrendered-emphasis: strict
```

語の中の記号（「2**10」「snake__case」）、前後が空白の記号、三つ以上並んだ記号（記入欄の「____」）、コードと引用の中の記号は指しません。
どのジャンルでも動きます。

# 日付の書き方が揃っていない（`date-format-consistency`）

**こんな文書に:** 予定の案内、計画書、報告書。表計算や予定表の画面から日付を写すと、そこだけ「2026/11/30」のような書き方が残ります。

## 元の文章

```markdown chaff-before
# 年末調整の書類の集め方

人事課からのお知らせです。今年の年末調整の書類を、次の日程で集めます。

書類は2026年11月9日に、各課の課長あてに配ります。
記入した書類は、2026/11/27までに人事課へ出してください。
出し忘れがあった人には、2026年12月4日に個別に連絡します。

給与の明細で差額を返すのは、2027年1月25日の給与日です。
```

## 直した文章

```markdown chaff-after
# 年末調整の書類の集め方

人事課からのお知らせです。今年の年末調整の書類を、次の日程で集めます。

書類は2026年11月9日に、各課の課長あてに配ります。
記入した書類は、2026年11月27日までに人事課へ出してください。
出し忘れがあった人には、2026年12月4日に個別に連絡します。

給与の明細で差額を返すのは、2027年1月25日の給与日です。
```

## 直し方

このお知らせの日付は、「2026年11月9日」のように年月日を漢字で区切っています。提出の締め切りだけが「2026/11/27」と斜線で区切られています。
いちばん大事な締め切りが、ほかの日付と違う見た目で書かれているので、読み手は同じ種類の日付なのかを確かめ直すことになります。予定表の画面から写した名残に見えます。

締め切りを、ほかの日付と同じ「2026年11月27日」に直しました。
chaff は、どちらの書き方が正しいかは決めません。年・月・日のそろった日付を比べ、文書の中で少ないほうを指します。

## 設定

少ないほうの日付が全体の一定の割合までなら、書き分け忘れと読んで指摘します。それより多いときは、表と本文のように使い分けていると読みます。

```yaml chaff-settings
rules:
  date-format-consistency: relaxed
```

`relaxed` にすると、少ないほうがもっと少ないときだけ指摘します。`strict` にすると、少ないほうが半分近くまで指摘します。見たくなければ `off` にします。
年だけや月日だけの日付、URL やコードの中の日付は比べません。どのジャンルでも動きます。

```text chaff-explain
$ npx chaffjs explain date-format-consistency --genre business/report

  日付の書き方が揃っていない   (date-format-consistency)

  一つの文書で「2026-10-02」と「2026年10月2日」、「Oct 2, 2026」と「10/2/2026」のように日付を二通りに書くと、読み手は同じ種類の日付なのかを確かめ、10/2 が十月二日なのか二月十日なのかも迷います。書き写した所や、あとから足した所に多い揺れです。どちらの書き方が正しいかは決めず、文書の中で少ないほうを指します。年・月・日のそろった日付だけを比べます。月の名前と元号は言語ごとの語彙表にあります。

  直しかた: 文書の中の日付を一つの書き方に揃えてください。

  書き直しの深さ: light（語と文を直す。構成と文体は残す）。chaff fix-plan --depth でこれより浅い深さを選ぶと、計画はこのルールを直さず、名前だけを挙げます。

  設定できる値:
    strict   少ないほうの書き方の日付が全体の 49% 以下なら指摘
  → normal   少ないほうの書き方の日付が全体の 34% 以下なら指摘
    relaxed  少ないほうの書き方の日付が全体の 20% 以下なら指摘
    off      見ない

  いまは normal です。

  変える:  npx chaffjs relax date-format-consistency --why "理由"
```

# 始まりと期間から計算した終わりが、書いた終わりと合わない（`duration-mismatch`）

**こんな文書に:** 契約書の契約の期間、宿泊の泊数、勤務の時間。始まりの日を変えたのに、括弧の中の終わりの日を前のままにする、という形がよくあります。

## 元の文章

```markdown chaff-before
# 駐車場賃貸借契約書

あさひ不動産株式会社（以下「甲」という。）と、株式会社のぞみ工務店（以下「乙」という。）は、甲が持つ駐車場の区画を乙が借りることについて、次のとおり契約を結ぶ。

## 第1条（区画）

甲は、さくら台第二駐車場の3番と4番の区画を、乙に貸す。

## 第2条（期間）

契約の期間は、2026年4月1日から1年間（2027年4月30日まで）とする。

## 第3条（賃料）

乙は、一区画につき月額15,000円の賃料を、毎月25日までに翌月分を甲に支払う。
```

## 直し方

4月1日から1年間なら、終わりは翌年の3月31日です。括弧の中は4月30日なので、1年と1か月になります。初めは5月1日からの契約で、始まりの日だけを4月1日に直したのでしょう。
期間と終わりの日のどちらが約束なのかが、契約書からは決まりません。4月分の賃料を払うのか、4月に区画を空けるのかで、甲と乙の読み方が分かれます。

直した文章では、終わりを2027年3月31日にしました。1年と1か月貸すつもりなら、期間のほうを直します。

## 設定

ふだんは「注意」として出します。`relaxed` にすると「参考」になり、`off` にすると見なくなります。

```yaml chaff-settings
rules:
  duration-mismatch: relaxed
```

一つの文に日付が二つと期間が一つあるとき、始まりに期間を足した日を終わりと比べます。終わりの日を含めて数える書き方、含めない書き方、初日を数えない書き方のどれとも合わないときだけ指摘します。「約3か月」のような目安の期間と、日付が三つ以上ある文は見ません。宿泊の泊数（10月12日から10月14日までは2泊）と、休憩を除いた勤務の時間も、同じように比べます。

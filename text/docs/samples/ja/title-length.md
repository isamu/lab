# 題や見出しが長すぎる（`title-length`）

**こんな文書に:** 技術記事、ブログ、社内の手引き。中身を全部伝えようとして、題に条件や説明まで詰め込みがちな文章です。

## 元の文章

```markdown chaff-before

押し入れで眠っていた、十年前のノートパソコンを使いました。
家族のスマートフォンで撮った写真を、毎晩このパソコンに集めています。

## 用意したもの

パソコンのほかに、外付けのハードディスクを一台買いました。
写真は年に三十ギガバイトほど増えるので、二テラバイトあれば当分は足ります。
```

## 直した文章

```markdown chaff-after
# 古いノートパソコンを家族の写真の置き場にした話

押し入れで眠っていた、十年前のノートパソコンを家庭用のサーバーにしました。
家族のスマートフォンで撮った写真を毎晩このパソコンに集め、外出先からも見られるようにしています。

## 用意したもの

パソコンのほかに、外付けのハードディスクを一台買いました。
写真は年に三十ギガバイトほど増えるので、二テラバイトあれば当分は足ります。
```

## 直し方

元の題は46字あり、何をしたのか、何のためか、何ができるようになったのかが全部入っています。
読み手は、題を目で拾って読むかどうかを決めます。長い題は一目で読めず、検索の結果や記事の一覧では途中で切れます。

直した文章では、題には「古いノートパソコンを家族の写真の置き場にした」という話の核だけを残しました。
家庭用のサーバーにしたこと、外出先から見られることは、本文の最初の二文に移しています。
題で興味を持った人は、すぐ下で詳しいことを読めます。

見出しの頭の番号（「第2章」「1.」）は数えません。英字の語は、一語を二文字と数えます。

## 設定

ブログの技術記事（`blog/tech`）では、題や見出しが40字を超えると指摘します。`strict` にすると30字、`relaxed` にすると50字からです。
報告書・プレスリリース・議事録・仕様書・論文は正式な題が長くなるので、上限を上げています。
法務・文学・話し言葉のジャンルと、見出しが質問になるよくある質問のページでは、既定で止めています。

```yaml chaff-settings
rules:
  title-length: relaxed
```

見ないことにするなら `title-length: off` です。コマンドでも変えられ、理由が chaff.yaml にコメントで残ります。

```bash
npx chaffjs relax title-length --why "正式な題を変えられない規程集のため"
```

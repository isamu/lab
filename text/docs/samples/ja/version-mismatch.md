# 説明の版とコードの版が違う（`version-mismatch`）

**こんな文書に:** 道具の使い方の説明、インストールの手順、社内の環境構築の手引き。新しい版を出したときに、説明かコード例の片方だけを直す、という形がよくあります。

## 元の文章

````markdown chaff-before
# kakeibo-cli

家計簿を、ターミナルからつけるための道具です。

## インストール

npm から最新版の 2.4.1 を入れます。

```bash
npm install --global kakeibo-cli@2.4.0
```

入れたら、`kakeibo --version` で版を確かめてください。
````

## 直し方

説明には「最新版の 2.4.1 を入れます」と書いてあるのに、すぐ下のコマンドは `kakeibo-cli@2.4.0` です。2.4.1 を出したときに、説明の文だけを直して、コマンドを直し忘れたのでしょう。
手順を読む人の多くは、説明を読まずにコマンドだけを写して実行します。このままでは、直したはずの不具合が残った古い版を入れ、2.4.1 で直った問題をもう一度報告することになります。

直した文章では、コマンドを `kakeibo-cli@2.4.1` にしました。

## 設定

ふだんは「注意」として出します。`strict` にすると「エラー」に、`relaxed` にすると「参考」になります。

```yaml chaff-settings
rules:
  version-mismatch: strict
```

コードブロックのすぐ上の段落に書いた版（2.4.1 のように点で三つに区切った番号）を、そのコードブロックにある版と比べます。コードに版がちょうど一つあり、段落の版と違うときに指します。「2.3.0 から 2.4.0 へ」のように版が二つあるコード、「20.0.0 以上」のような範囲の端、「Node.js 18.17.0 が必要」のような別のプログラムの版は比べません。
法令、論文、文学、講演のジャンルでは止めています。変更履歴の版の並びは `version-order` が見ます。

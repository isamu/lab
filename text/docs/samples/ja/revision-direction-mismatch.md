# 修正の向きと表の数字が逆（`revision-direction-mismatch`）

**こんな文書に:** 業績予想の修正のお知らせ、配当予想の修正、計画の見直しの報告。去年の発表文を写して数字だけ差し替えると、「上方修正」の語が表と逆を向いたまま残ります。

## 元の文章

```markdown chaff-before
# 通期の業績予想の修正に関するお知らせ

## 修正の内容

2027年3月期の通期の業績予想を上方修正します。

| 項目 | 前回予想 | 今回予想 |
| --- | --- | --- |
| 売上高（百万円） | 5,200 | 5,000 |
| 営業利益（百万円） | 410 | 360 |

## 修正の理由

主力の業務用冷蔵庫で、部品の調達が遅れ、下期の出荷が計画を下回る見込みとなりました。
```

## 直した文章

```markdown chaff-after
# 通期の業績予想の修正に関するお知らせ

## 修正の内容

2027年3月期の通期の業績予想を下方修正します。

| 項目 | 前回予想 | 今回予想 |
| --- | --- | --- |
| 売上高（百万円） | 5,200 | 5,000 |
| 営業利益（百万円） | 410 | 360 |

## 修正の理由

主力の業務用冷蔵庫で、部品の調達が遅れ、下期の出荷が計画を下回る見込みとなりました。
```

## 直し方

文は「上方修正します」と言っていますが、表では売上高が前回の5,200から今回の5,000へ下がっています。修正の理由も、出荷が計画を下回る話です。
株主や記者は、見出しの近くの「上方修正」を先に読みます。表を読んだ人との間で受け取り方が割れ、訂正のお知らせを出すことになります。

表と理由が下がる向きで一致しているので、文の語を「下方修正」に直しました。
項目によって向きが違うなら、「売上高を下方修正し、営業利益を上方修正します」のように、項目ごとに書きます。

## 設定

ふだんは「注意」として出します。`strict` にすると「エラー」、`relaxed` にすると「参考」になります。

```yaml chaff-settings
rules:
  revision-direction-mismatch: strict
```

前回予想と今回予想の列（または行）を持つ表と、同じ節に書いた修正の向きの語（上方修正、増額修正、下方修正、減額修正）を比べます。
文が項目を名指していればその項目を、名指していなければ表の最初の項目を見ます。
節の中に上と下の向きの語が両方あるとき、升が「未定」のように数でないとき、値が変わっていないときは言いません。文芸のジャンルでは、はじめから動きません。

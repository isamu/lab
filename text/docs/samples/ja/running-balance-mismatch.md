# 残高が前の行から計算した値と合わない（`running-balance-mismatch`）

**こんな文書に:** 小口現金の出納帳、通帳や入出金の明細、ローンの返済予定表、在庫の受け払いの表。電卓で引いた結果を写すときに、数字の並びを取り違える、という形がよくあります。

## 元の文章

```markdown chaff-before
# 小口現金出納帳（11月）

| 日付 | 摘要 | 入金 | 出金 | 残高 |
| --- | --- | --- | --- | --- |
| 11月1日 | 前月から繰越 | | | 30,000円 |
| 11月4日 | 切手（84円×50枚） | | 4,200円 | 25,800円 |
| 11月8日 | 来客用の茶菓子 | | 2,160円 | 23,640円 |
| 11月12日 | 宅配便の送料 | | 1,480円 | 22,610円 |
| 11月15日 | 現金の補充 | 10,000円 | | 32,160円 |
| 11月20日 | 電池と延長コード | | 3,278円 | 28,882円 |
```

  ⚠  残高が前の行から計算した値と合わない

     残高「22,610円」は、前の行の残高とこの行の金額からは 22,160円 です
     返済予定表の「お支払後の残高」、通帳や入出金明細の「残高」、在庫表の「在庫」は、前の行の残高にその行の動きを足し引きした値です。読み手は引き算し直さずに信じます。一つの行の数字だけを直したとき、桁を打ち間違えたとき、行を別の表から写したときに食い違います。どの列が残高で、どの列がその行の動きかは、列の見出しの語（残高、元金、返済額、利息、入金、出金、Balance、Principal、Payment、Interest、Deposit、Withdrawal）だけで決めます。列の並びでは決めません。元金の列があれば、残高は前の行の残高から元金を引いた値です。元金の列が無く、利息の列も無ければ、支払額を引いた値です。入金と出金の列のある表では、前の行の残高に入金を足し、出金を引いた値です（空の升と「-」は0）。書いた数はどれも、最後の桁の半分までの丸めを認めます。言うのは表ごとに最初に合わない行だけです。一つの行の残高を打ち間違えると次の行も合わなくなるので、そこで止めます。

## 直し方

11月8日の残高23,640円から送料1,480円を引くと、11月12日の残高は22,160円です。表には22,610円と書いてあり、「1」と「6」が入れ替わっています。次の行からは正しい残高に戻っているので、表の一番下だけを見ても誤りは分かりません。
出納帳は、月末に手元の現金と残高を合わせるための表です。途中の一行が違うと、どこで合わなくなったのかを一行ずつ確かめ直すことになります。

直した文章では、11月12日の残高を22,160円にしました。chaff は表ごとに最初に合わない行だけを指すので、ほかにも誤りがあれば、直したあとにもう一度確かめます。

## 設定

ふだんは「注意」として出します。`strict` にすると「エラー」に、`relaxed` にすると「参考」になります。

```yaml chaff-settings
rules:
  running-balance-mismatch: strict
```

どの列が残高で、どの列がその行の動きかは、列の見出しの語（残高、元金、返済額、入金、出金など）だけで決めます。入金と出金の列のある表では、前の行の残高に入金を足し出金を引いた値と比べます。空の升と「-」は0と読み、書いた数はどれも最後の桁の半分までの丸めを認めます。日付の列も回の列も無い表、一つの列が両方の向きを書く表、合計の行は比べません。
文学のジャンルでは止めています。期首と期末の残高のまとめは `closing-balance-mismatch` が見ます。

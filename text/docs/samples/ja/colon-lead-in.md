# コロンで箇条書きへ渡す文が多い（`colon-lead-in`）

**こんな文書に:** ブログ、ふりかえり、社内の報告。AI に下書きさせると、節ごとに「以下のとおりです：」で箇条書きへ渡す形になります。

## 元の文章

```markdown chaff-before
# 社内の手順書を書き直した

経理課の手順書は、十年前に書いたものに、担当が代わるたびに書き足してきました。
今年の春に入った人が、手順書を読んでも月末の締めの作業を進められなかったので、全部を書き直すことにしました。
かかったのは、課の四人で二か月です。

## 困っていたこと

最初に、新人と、前の年に入った人に、どこで止まったかを聞きました。
二人とも、手順書を読むより先に隣の席の人に聞いていたそうです。
聞いて分かった、困っていたことは以下のとおりです：

- 同じ作業が、別の場所に違う手順で二回書いてある
- 画面の写真が古く、ボタンの名前がいまのシステムと合わない
- 誰に聞けばよいかが書いていない
- 締めの日が休日にずれる月の扱いが無い

## 書き直しの方針

古い手順書を直すより、一から書くほうが早いと判断しました。
まず、作業を全部書き出しました。
重なりを除くと、四十二です。
書き直すときに決めたことは次のとおりです：

- 一つの作業は一つのページにだけ書く
- 画面の写真は使わず、ボタンの名前を文字で書く

## 確かめ方

書き終えたら、書いた人ではない人に使ってもらうことにしました。
書いた人は、知っていることを無意識に飛ばしてしまうからです。
書き直したあとの確かめ方は以下のとおりです：

- 新人に、手順書だけを見て締めの作業をしてもらう
- 止まった所に印を付けてもらい、そのページを直す
- 次の月にもう一度やってもらう

二回目は、誰にも聞かずに最後まで進められました。
直したのは九ページです。
かかった時間は、一回目の半分ほどでした。
```

## 直し方

元の文章は、三つの節がどれも「〜は以下のとおりです：」「〜は次のとおりです：」で箇条書きへ渡しています。
節ごとにこの形が続くと、説明は箇条書きの前置きだけになり、項目どうしの繋がりが書かれません。
たとえば「困っていたこと」の四項目は、どれが新人を一番止めていたのかが分かりません。

直した文章では、箇条書きを文に戻しました。
同じ作業が二回書いてあったことを、「どちらが正しいのか分からなかったから」と、隣の席の人に聞いていた理由として書いています。
方針の二つも「名前が変わっても、文字なら検索して直せます」と、なぜそう決めたのかまで書きました。
手順や部品の一覧のように、本当に並べるものは箇条書きのままでかまいません。

## 設定

コロンで箇条書きへ渡す文が、1000字あたり2個を超えると指摘します。前置きのある節が3つより少ない文書と、短い文書（500字未満）は測りません。

```yaml chaff-settings
rules:
  colon-lead-in: relaxed
```

`relaxed` にすると1000字あたり4個まで、`strict` なら1個までです。
前置きのある節の数の下限は、`options` の `min_sections` で変えられます。

```yaml chaff-settings
options:
  colon-lead-in:
    min_sections: 4
```

コロンで終わらない前置き（「次のとおりとする。」）、一行に立つ名詞の札（**メリット：**）、義務を述べる前置き（「担当者は次を行わなければならない：」）は数えません。
法令・契約（`legal`）、手順書（`docs`）、仕様書（`technical/spec`）、文学（`literature`）、講演（`speech`）のジャンルでは、はじめから動きません。

このルールは AI らしさの目安にも数えます。文章全体の目安は `npx chaffjs ai-score post.md` で見られます。

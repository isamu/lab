# 制定日が改定日より後（`date-stamp-order`）

**こんな文書に:** 利用規約、社内の規程、個人情報の方針。改定の日付を書き足すときに、制定の日付まで書き換えてしまう、という形がよくあります。

## 元の文章

```markdown chaff-before
# あおば図書館 利用規約

## 第1条（目的）

この規約は、あおば図書館の利用について定めます。

## 第2条（貸出）

1. 本の貸出は、1人10冊まで、2週間までとします。
2. 返却が遅れた場合は、返却の日まで新しい貸出をしません。

2025年4月1日 制定

2024年10月1日 最終改定
```

## 直した文章

```markdown chaff-after
# あおば図書館 利用規約

## 第1条（目的）

この規約は、あおば図書館の利用について定めます。

## 第2条（貸出）

1. 本の貸出は、1人10冊まで、2週間までとします。
2. 返却が遅れた場合は、返却の日まで新しい貸出をしません。

2015年4月1日 制定

2024年10月1日 最終改定
```

## 直し方

末尾の日付は「2025年4月1日 制定」「2024年10月1日 最終改定」で、定めた日が直した日より後になっています。まだ無い規約を直したことになり、読む人は、今の規約がいつから使われているのかが分かりません。改定のたびに日付を書き換えるうちに、制定の年まで書き換えてしまったのでしょう。
規約の日付は、利用者との行き違いがあったときに、どの版が当てはまるかを決める根拠になります。どちらの日付が違っているかは機械には分からないので、chaff は両方の行を指します。

直した文章では、制定の日付を元の「2015年4月1日」に戻しました。改定の日付のほうが誤りなら、そちらを直します。

## 設定

ふだんは「エラー」として出します。`relaxed` にすると「注意」になり、`off` にすると見なくなります。

```yaml chaff-settings
rules:
  date-stamp-order: relaxed
```

日付と制定・改定の語だけの行を読みます。「2020年12月21日に計画を策定」のように、ほかに何かが書かれた行と年の無い日付は読みません。7行以上離れた二つの行は、一つのファイルにまとめた別の文書のものと見て比べません。施行日は改定日より後になってよいので、比べません。

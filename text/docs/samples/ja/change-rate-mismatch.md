# 増減率が二つの値と合わない（`change-rate-mismatch`）

**こんな文書に:** 月次や年次の報告、プレスリリースの実績、営業の振り返り。目標の率や前月の率を書いた文を写して、数字だけを今月の値に差し替える、という形がよくあります。

## 元の文章

```markdown chaff-before
# 会員サービスの月次報告（10月）

## 会員数

10月末の会員数は2,880人となり、前年同月の2,400人から15%増えました。
増えた会員の多くは、9月に始めた紹介の特典から入会した方です。

## 来月の予定

11月は、紹介の特典を続けながら、退会した方への案内を見直します。
```

  ⚠  増減率が二つの値と合わない

     「15%」と書いていますが、二つの値からは 20% です
     「前年同月の1,000社から20%増えて1,200社」のように、もとの値・今の値・増減率を一つの文に書くと、読み手は率を確かめずに信じます。数字を一つだけ更新したとき、率だけを去年の文書から写したときに食い違います。一つの文に、もとの値（「から」「に比べて」「前年の」の付いた値）、同じ単位の今の値、向きの語（増加、減少）の付いた百分率が一つずつあるとき、二つの値から率を計算して比べます。率のそばにもとの値が無くても、「昨年の100万円から今年は150万円になり、前年比50%の増加」「2025年度は100万円、2026年度は150万円で」のように二つの値が並んですぐ後に率が続くなら読みます（年が書いてあれば早い年の値がもとの値）。今の値は率の後ろでも、「前年同期の2,400百万円から10.0%増加し、2,640百万円となりました」のように動いた先と分かれば読みます。値は書いた桁までの丸めを認めます（12億円は11.5億円から12.5億円のどれか）。表も読みます。見出しの語で前期の列（前期、前年同期）、当期の列（当期、当第2四半期）、増減率の列（増減率、前年同期比）が一つずつ分かる表（見出しの語が無くても、二つの列の見出しに年が一つずつ書いてあれば早い年の列が前期）では、行ごとに二つの値から率を計算し、書いた率と比べます。△・▲・−の付いた率は減少です。「増減」の列は、升に % があるときだけ率と読みます。

## 直した文章

```markdown chaff-after
# 会員サービスの月次報告（10月）

## 会員数

10月末の会員数は2,880人となり、前年同月の2,400人から20%増えました。
増えた会員の多くは、9月に始めた紹介の特典から入会した方です。

## 来月の予定

11月は、紹介の特典を続けながら、退会した方への案内を見直します。
```

## 直し方

会員数は前年同月の2,400人から2,880人に増えたので、増えた割合は20%です。文には「15%増えました」と書いてあります。人数を今月の値に差し替えたとき、率だけを前の報告のまま残したのでしょう。
報告を読む人は、率を見て伸びが良いのか悪いのかを判断し、人数から割り算し直すことはまずありません。15%と20%では、紹介の特典の効果の受け取り方が変わります。

直した文章では、率を20%にしました。人数のほうが誤りなら、人数を直します。

## 設定

ふだんは「注意」として出します。`strict` にすると「エラー」に、`relaxed` にすると「参考」になります。

```yaml chaff-settings
rules:
  change-rate-mismatch: strict
```

一つの文に、もとの値（「から」「に比べて」「前年の」の付いた値）、同じ単位の今の値、向きの語（増加、減少）の付いた百分率が一つずつあるときに、二つの値から率を計算して比べます。値は書いた桁までの丸めを認めます。表では、前期、当期、増減率の列が見出しの語で一つずつ分かるとき、行ごとに比べます。「前年比20%増」のように値が一つしか無いもの、ポイントの差、倍は見ません。
文学のジャンルでは止めています。利益率のような割り算は `ratio-mismatch` が見ます。

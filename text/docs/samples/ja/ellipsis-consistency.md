# 省略記号の書き方が混ざっている（`ellipsis-consistency`）

**こんな文書に:** 社員の紹介記事、取材の記事、お客さまの声。話し言葉をそのまま載せる記事では、書き起こした人ごとに「……」と「・・・」が混ざりやすくなります。

## 元の文章

```markdown chaff-before
# パン工房の朝は四時に始まる

駅前の店で働いて八年になる、製造担当の大西さんに話を聞きました。

最初の一年は、生地をこねる力加減が分からなかったそうです。
「毎朝、先輩の手もとをじっと見ていました……。言葉で教わるより、見て覚えるほうが早かったですね」

いちばん好きなパンを聞くと、少し考えてから答えてくれました。
「うーん……。やっぱり、塩バターロールでしょうか」

これからの目標は、地元の小麦だけで作る食パンです。
「まだ試している途中なんですけど・・・。来年の春には、お店に並べたいと思っています」
```

## 直し方

この記事では、話の間を「……」で表しています。最後の一言だけ「・・・」と中黒を三つ並べています。
読み手は、そこだけ違う意味の間なのかと気になります。記事のあとで「……」を検索して手直しするときにも、この一か所を取りこぼします。

少ないほうの「・・・」を、ほかと同じ「……」に直しました。
chaff は、どちらの記号が正しいかは決めません。文書の中で少ないほうを指します。

## 設定

少ないほうが全体の一定の割合までなら、書き分け忘れと読んで指摘します。それより多いときは、わざと使い分けていると読みます。

```yaml chaff-settings
rules:
  ellipsis-consistency: relaxed
```

`relaxed` にすると、少ないほうがもっと少ないときだけ指摘します。`strict` にすると、少ないほうが半分近くまで指摘します。見たくなければ `off` にします。
どのジャンルでも動きます。コードの中は見ません。

```text chaff-explain
$ npx chaffjs explain ellipsis-consistency --genre blog/owned-media

  直しかた: 文書の多いほうの書き方に合わせてください。

  書き直しの深さ: light（語と文を直す。構成と文体は残す）。chaff fix-plan --depth でこれより浅い深さを選ぶと、計画はこのルールを直さず、名前だけを挙げます。

  いまは normal です。

  変える:  npx chaffjs relax ellipsis-consistency --why "理由"
```

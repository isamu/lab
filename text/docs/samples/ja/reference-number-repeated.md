# 明細の表で、同じ領収書・請求書の番号が二つの行にある（`reference-number-repeated`）

**こんな文書に:** 経費の精算書、請求の明細、支払いの一覧。行を写して内容と金額だけを書き換えると、領収書の番号が前の行と同じまま残ります。

## 元の文章

```markdown chaff-before
# 4月分の経費精算

大阪の取引先を訪ねたときの経費を精算します。領収書は、経理課の受付箱に入れました。

| 日付 | 領収書番号 | 内容 | 金額 |
| --- | --- | --- | --- |
| 2026年4月6日 | K-118 | 新幹線代 | 14,720円 |
| 2026年4月6日 | K-119 | 宿泊代 | 9,800円 |
| 2026年4月7日 | K-119 | タクシー代 | 2,350円 |
| 2026年4月7日 | K-121 | 会議室の利用料 | 5,500円 |

合計は32,370円です。
```

  ⚠  明細の表で、同じ領収書・請求書の番号が二つの行にある

     「領収書番号」の「K-119」は、8 行目の行にもあります
     経費精算書や請求の明細では、一つの行が一枚の領収書や請求書で、その番号は表の中で一度しか出てきません。同じ番号が二つの行にあれば、同じ領収書を二度請求しているか、行を写して番号を直し忘れたかのどちらかです。どちらも、読み手は番号を一つずつ照らし合わせないかぎり気づきません。列は見出しの語（領収書番号、伝票番号、請求書番号、Receipt no.、Invoice no.、Ref.）だけで決めます。番号は数字を一つ以上含む升だけを読み、空の升、「-」、「なし」、「N/A」は番号として数えません。全角と半角、大文字と小文字、空白は同じ番号として比べます。

## 直した文章

```markdown chaff-after
# 4月分の経費精算

大阪の取引先を訪ねたときの経費を精算します。領収書は、経理課の受付箱に入れました。

| 日付 | 領収書番号 | 内容 | 金額 |
| --- | --- | --- | --- |
| 2026年4月6日 | K-118 | 新幹線代 | 14,720円 |
| 2026年4月6日 | K-119 | 宿泊代 | 9,800円 |
| 2026年4月7日 | K-120 | タクシー代 | 2,350円 |
| 2026年4月7日 | K-121 | 会議室の利用料 | 5,500円 |

合計は32,370円です。
```

## 直し方

宿泊代とタクシー代の行に、同じ領収書番号「K-119」があります。
明細の一つの行は一枚の領収書なので、同じ番号は一度しか出てこないはずです。経理の人から見ると、同じ領収書を二度請求しているのか、番号を直し忘れたのかが分かりません。確かめるために、精算が止まります。

手元の領収書を確かめると、タクシー代は K-120 だったので、その行の番号を直しました。
本当に同じ領収書を二度書いていたなら、一方の行を消します。

## 設定

ふだんは「注意」として出します。`strict` にすると「エラー」、`relaxed` にすると「参考」になります。

```yaml chaff-settings
rules:
  reference-number-repeated: strict
```

列は見出しの語（領収書番号、伝票番号、請求書番号）だけで決めます。「番号」だけの列や科目のコードは読みません。
全角と半角、大文字と小文字、空白の違いは同じ番号として比べます。空の升、「-」、「なし」は番号として数えません。
一枚の伝票の行をまとめて書いた表（一つの番号が三つ以上の行にあるもの）は比べません。文芸のジャンルでは、はじめから動きません。

# 定義したのに使っていない語（`unused-definition`）

**こんな文書に:** 契約書、利用規約、仕様書。条を書き進めるうちに別の語で言い換えてしまい、定義だけが残る形がよくあります。

## 元の文章

```markdown chaff-before
# 翻訳業務委託契約書

株式会社ことのは（以下「甲」という。）と翻訳者の北原（以下「乙」という。）は、製品マニュアルの翻訳について、次のとおり契約を結ぶ。

## 第1条（定義）

この契約で「成果物」とは、乙が翻訳して甲に納める英語の原稿をいう。

## 第2条（納品）

乙は、2026年6月30日までに、翻訳した原稿を電子メールで甲に納める。

## 第3条（検収）

甲は、納められた原稿を受け取った日から10日以内に確認し、その結果を乙に知らせる。

## 第4条（著作権）

翻訳した原稿の著作権は、委託料の支払いが済んだ時に、乙から甲に移る。
```

## 直した文章

```markdown chaff-after
# 翻訳業務委託契約書

株式会社ことのは（以下「甲」という。）と翻訳者の北原（以下「乙」という。）は、製品マニュアルの翻訳について、次のとおり契約を結ぶ。

## 第2条（納品）

乙は、2026年6月30日までに、成果物を電子メールで甲に納める。

## 第3条（検収）
```

## 直し方

この契約書は、第1条で「成果物」を定義しています。
ところが本文では、第2条から第4条まで「翻訳した原稿」「納められた原稿」と書いていて、「成果物」は一度も出てきません。
定義は、本文で同じものを同じ語で呼ぶために置くものです。使われない定義は、読み手に覚えさせるだけで何も決めていません。
それどころか、「翻訳した原稿」と「成果物」は同じものなのか、たとえば下訳や用語集は含むのかという疑問を残します。

直した文章では、本文の三か所を「成果物」に揃えました。
本文で使う語のほうが分かりやすいと考えるなら、反対に定義のほうを消すか、その語で定義し直します。

## 設定

この規則は、指摘の重さだけが変わります。ふだんは「参考」として出し、`strict` にすると「注意」になります。

```yaml chaff-settings
rules:
  unused-definition: strict
```

「X」とは、以下「X」という、のような定義の書き方で書いた語だけを見ます。見出しの中に出てくる語も、使った所に数えます。
同じ語を二度定義した所は、`duplicate-definition` が言います。
用語集（`docs/glossary`）のジャンルでは、ほかの文書が使う語を定義するのが役目なので動きません。

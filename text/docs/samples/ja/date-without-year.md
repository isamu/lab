# 年の無い日付（`date-without-year`）

**こんな文書に:** 計画書、日程の案内、報告書。年の暮れから次の年にかけての予定を並べたときに、年を書かずに月と日だけで書く形がよくあります。

## 元の文章

```markdown chaff-before
# 新しい受発注システムへの切り替えの日程

受発注の仕組みを、来年の初めに新しいシステムへ切り替えます。各店の担当の方は、次の日程を手帳に書き入れてください。

- 2026年12月4日：各店の担当向けの説明会
- 2026年12月18日：新しいシステムでの試しの発注
- 1月13日：新しいシステムへの切り替え

切り替えの前の日までに、古いシステムに残った注文を済ませてください。
```

## 直した文章

```markdown chaff-after
# 新しい受発注システムへの切り替えの日程

受発注の仕組みを、来年の初めに新しいシステムへ切り替えます。各店の担当の方は、次の日程を手帳に書き入れてください。

- 2026年12月4日：各店の担当向けの説明会
- 2026年12月18日：新しいシステムでの試しの発注
- 2027年1月13日：新しいシステムへの切り替え

切り替えの前の日までに、古いシステムに残った注文を済ませてください。
```

## 直し方

この日程の説明会と試しの発注は2026年の12月ですが、一番大事な切り替えの日は「1月13日」としか書いてありません。
並び順から2027年の1月と読めそうですが、書いてあるのは「2026年」だけです。日付だけを拾い読みした人は、すでに過ぎた2026年の1月のことかと迷います。
この案内を手帳に写す人や、来年になってから読み返す人には、年が無いことがそのまま迷いになります。

直した文章では、切り替えの日に「2027年」と年を書きました。
年をまたぐ日付には、たとえほかの日付から読めそうでも、年を書いておくと取り違えが起きません。

## 設定

この規則は、指摘の重さだけが変わります。ふだんは「参考」として出し、`strict` にすると「注意」になります。

```yaml chaff-settings
rules:
  date-without-year: strict
```

年のある日付がみな同じ年で、年をまたがない文書では、年の無い日付を指しません。どの年か読み手に分かるからです。
「2026年度の予定」のように見出しが年を名指す節の日付や、「毎年4月1日」のようなどの年のものでもない日付も指しません。
議事録や手紙のように頭に文書の日付を書くジャンルでは、その日付から5か月以内の月日もその年と読みます。
どのジャンルでも動きます。

```text chaff-explain

  直しかた: 年を書いてください（2027年1月15日）。

  書き直しの深さ: light（語と文を直す。構成と文体は残す）。chaff fix-plan --depth でこれより浅い深さを選ぶと、計画はこのルールを直さず、名前だけを挙げます。

    strict   注意
  → normal   参考
    relaxed  参考
    off      見ない

  オプション（chaff.yaml の options で決めます）:
    dated_genres: [business/meeting-notes, business/email, speech]   （既定）

  決める:  chaff.yaml に options: { date-without-year: { <名前>: <値> } } を書く

  いまは normal です。

  変える:  npx chaffjs relax date-without-year --why "理由"
```

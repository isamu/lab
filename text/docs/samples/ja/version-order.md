# 版の並びが前後している（`version-order`）

**こんな文書に:** 変更履歴、リリースノート、仕様書の改訂の記録。新しい項を書き足すときに、版の番号を打ち間違える、という形がよくあります。

## 元の文章

```markdown chaff-before
# 変更履歴

このファイルには、kakeibo-cli の版ごとの変更を新しい順に書きます。

## 2.4.0 - 2026-10-20

- 月ごとの集計を CSV で書き出せるようにしました。

## 2.3.1 - 2026-08-02

- 外貨の金額で、小数点以下が消える不具合を直しました。

## 2.5.0 - 2026-06-15

- 費目に色を付けられるようにしました。

## 2.2.0 - 2026-04-01

- 予算の機能を足しました。
```

## 直した文章

```markdown chaff-after
# 変更履歴

このファイルには、kakeibo-cli の版ごとの変更を新しい順に書きます。

## 2.4.0 - 2026-10-20

- 月ごとの集計を CSV で書き出せるようにしました。

## 2.3.1 - 2026-08-02

- 外貨の金額で、小数点以下が消える不具合を直しました。

## 2.3.0 - 2026-06-15

- 費目に色を付けられるようにしました。

## 2.2.0 - 2026-04-01

- 予算の機能を足しました。
```

## 直し方

変更履歴は新しい順に並んでいるのに、上から三つ目の版が「2.5.0」で、前の「2.3.1」より新しくなっています。日付は2026年6月15日で、並びの位置も2.2.0と2.3.1の間なので、2.3.0と書くつもりで打ち間違えたのでしょう。
変更履歴を読む人は、自分の使っている版より新しい項を拾い読みして、何が変わったかを確かめます。2.5.0が並びの途中にあると、まだ出ていない版の変更なのか、色の機能がいつ入ったのかを取り違えます。

直した文章では、その版を2.3.0にしました。版の番号が正しく、置き場所が違うだけなら、項を正しい位置へ移します。

## 設定

ふだんは「注意」として出します。`strict` にすると「エラー」に、`relaxed` にすると「参考」になります。

```yaml chaff-settings
rules:
  version-order: strict
```

見出しや箇条書き、表の行の先頭に書いた版（3.2.0、v3.2.0、[3.2.0]）を並びとして読み、向きは多いほうで決めて、その向きの最も長い並びに入らない版を指します。見出しは同じ深さどうしを比べます。並べた版が三つ未満のもの、上がりと下がりが同じ数のもの、文の中の版、コードブロックの中の例、「3.1」のように点で三つに区切っていない番号は見ません。
法令、論文、文学、講演のジャンルでは止めています。説明とコードの版の食い違いは `version-mismatch` が見ます。

```text chaff-explain

    off      見ない

  変える:  npx chaffjs relax version-order --why "理由"
```

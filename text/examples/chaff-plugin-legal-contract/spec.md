# chaff-plugin-legal-contract — 方針

このパックは、日本の契約書を chaff で機械検査可能な形に揃えることを目的とする。

## 射程

次の契約書種別を対象にする。

- **NDA（秘密保持契約）** — v0 で対応 ✅
- **業務委託契約書** — v1 で対応 ✅
- **利用規約** — v2 で対応 ✅
- **プライバシーポリシー** — v2 で対応 ✅

対象外:

- 英文契約（将来の別パックで検討）
- 法令・判例（chaff 本体の legal/statute, legal/judgment で既に扱える）
- 内部規程・社内規則（別パックの候補）

## 設計方針

### chaff の守備範囲に収める

このパックが指摘するのは、機械で判定できる項目に限る。

- 表記ゆれ（甲乙 vs 役割名）
- 必須条項の有無（キーワード検索ベース）
- 冗長表現（固定パターン）

意味の整合、法的な妥当性、個別事情の反映は人間 or LLM の仕事。chaff はその前段で機械的な衛生を担う。

### 契約書種別ごとに別ルール

NDA、業務委託契約書、利用規約、プライバシーポリシーの必須条項は、それぞれ別のルール ID で分ける。

- `legal-contract/required-clauses-nda`
- `legal-contract/required-clauses-outsourcing`
- `legal-contract/required-clauses-tos`
- `legal-contract/required-clauses-privacy`

同じ `legal/contract` ジャンルの中で、文書ごとに house style を切り替える前提。house style は `nda` / `outsourcing` / `tos` / `privacy` の 4 つを用意しており、使わないルールは `off`、該当するルールだけ `strict` に設定している。

### テンプレートは「chaff が読める構造」で書く

chaff は条・項・号の番地付き構造を読める。テンプレートもその構造で書いておけば、空欄埋めで作った契約書も同じ構造を保つ。

- 第 1 条、第 2 条... は Markdown の `## 第 N 条（見出し）` で書く
- 項は番号付き箇条書き
- 空欄は `___________` で統一（検出用のマーカー）

### 言語

- ルールの `name` / `why` / `message` / `how_to_fix` は日本語 + 英語で書く（chaff 本体の作法に揃える）
- ただし契約書は日本語のみ対象なので、英語側は "N/A" でよい

## バージョニング

- v0: NDA ✅
- v1: + 業務委託契約書 ✅
- v2: + 利用規約・プライバシーポリシー ✅
- v3: 業種別派生（SaaS 向け利用規約、個人情報取扱委託契約、SES 契約、ソフトウェア開発契約など、要望ベースで追加）

## 既知の限界

- `required-clauses-nda` はキーワードベースなので、同じ趣旨を違う言葉で書いた場合は検出できない。拾う側に倒す
- `mono-to-suru-filler` は過検出より見逃し寄り。意図があって残している「ものとする」を誤検出しない範囲に抑えている
- 当事者が 3 者以上（甲乙丙）の契約には未対応
- 英文との並行契約（二言語契約書）には未対応

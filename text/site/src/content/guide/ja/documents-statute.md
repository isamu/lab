# 社内規程・規則でできること

社内規程や規則は、条に番号を振り、条どうしで引き合う文書です。
chaff は、その番号と参照がかみ合っているかを機械で確かめます。
ジャンルは `legal/statute` です。法令、通達も同じジャンルで見ます。

## 規程でよく起きる崩れ

規程は、改正のたびに条を削ったり足したりします。そのとき、番号と参照がずれます。

| 崩れ | 例 |
| --- | --- |
| 番号が飛ぶ | 第3条を消したのに、番号を振り直していない（第2条の次が第4条） |
| 無い条を引く | 消した条や、まだ書いていない条を「第9条に定める台帳」と引いている |
| 同じ語を二度定義する | 「備品」を第1条と第4条で別々に定義し、中身が食い違う |

どれも、読み手には正しいほうが分かりません。書いた人に聞くしかなくなります。
長い規程ほど、人の目では見落とします。

## chaff が見ること、見ないこと

このジャンルでは、次のルールが動きます。どれも、規程を番地の付いた木にして読むルールです。

| ルール | 見つけるもの |
| --- | --- |
| `numbering-gap` | 番号の抜けや重なり |
| `dangling-reference` | 文書に無い条を指している参照 |
| `duplicate-definition` | 同じ語を二度定義している所 |
| `date-weekday-mismatch` | 日付に添えた曜日が、暦と合っていない所 |
| `total-mismatch` | 合計が内訳の和と合わない所 |
| `dangling-figure-reference` | 文書に無い図・表・別表（別表第一など）を指す所 |
| `date-range-reversed` | 期間の終わりが始まりより前の所 |

見ないことも決めてあります。

- 文章は書き換えません。直すのは書いた人です。
- 規程の中身が妥当か、法律に合っているかは見ません。読んで決めるのは人です。
- 二つの定義のどちらが正しいかは決めません。二度目の定義の場所を示すだけです。
- 第1条の「前条」のように、指す先が決まらない参照は指摘しません。当て推量で誤りを言わないためです。
- 「旅費規程第9条」のように文書名を添えた参照は、別の文書を指すので、この文書の中を探しません。
- 受け身や、長い漢字の連なりは見ません。規程ではそれが決まった書き方だからです。

## かけてみる

準備がまだなら、先に[準備する](./documents#準備する)を済ませます。
次の規程を `kitei.md` という名前で保存しました。崩れを 3 つ入れてあります。

```markdown file=kitei.md
# 備品管理規程

## 第1条（目的）

この規程は、会社の備品の貸出と返却の手続きを定める。
２　この規程において「備品」とは、会社が所有するパソコン、カメラその他の機器をいう。

## 第2条（貸出）

社員は、第9条に定める台帳に記入して、備品を借りることができる。

## 第4条（返却）

借りた備品は、借りた日から7日以内に返さなければならない。
２　この規程において「備品」とは、1万円以上の機器をいう。
```

文書を置いたフォルダで、次のコマンドを打ちます。

```bash
npx chaffjs kitei.md --genre legal/statute    kitei.md を社内規程として見る
```

画面には、次のように出ます。

```
$ npx chaffjs kitei.md --genre legal/statute

kitei.md   legal/statute · 日本語   ジャンルは--genreから

─── 10 行目 ──────────────────────────────────────────────────

    第9条に定める台帳に記入して、備品を借りることができる。

  ✖  参照先が無い

     「第9条」（番地 9）はこの文書にありません
     「第12条に定める」のような参照は、その条が文書に無ければ読み手を行き止まりにします。条を消したり番号を振り直したりしたときに、参照だけが古い番号のまま残ることがよくあります。chaff は文書を番地の付いた木にして（chaff tree）、参照の番地が木にあるかを見ます。見出しに「1 目的」と番号を振っただけで「第N条」と書いた条の無い文書（ガイドラインや通達）の「法第2条」は、別の文書の条なので探しません。

     → 正しい番号に直すか、参照を消してください。他の文書を指しているなら、「民法第3条」のように文書名を添えると読み手に伝わります。

     このルールをゆるめる:  npx chaff relax dangling-reference


─── 12 行目 ──────────────────────────────────────────────────

    ## 第4条（返却）

  ✖  番号の抜け・重なり

     「第2条」の次が「第4条」です（3 番目のはず）
     第3条の次が第5条、(a) の次が (c)、同じ第2項が二つ。番号が飛ぶか重なると、読み手は何かが消えたのか、参照がどちらを指すのかを判断できません。同じ親の中で並ぶ番号だけを比べます。枝番号（第3条の2）は並びの外として扱います。

     → 番号を振り直してください。削った条を欠番として残すなら、「第4条（削除）」のように番号だけを残すと読み手に伝わります。

     このルールをゆるめる:  npx chaff relax numbering-gap


─── 15 行目 ──────────────────────────────────────────────────

    「備品」とは、1万円以上の機器をいう。

  ⚠  同じ語の二重定義

     「備品」は 6 行目でも定義されています
     同じ語を二か所で定義すると、二つの定義が食い違っていないかを読み手が確かめなければなりません。長い契約書では、後から足した定義が先の定義と少しずれることがよくあります。中身が食い違っているかは機械では決まらないので、chaff は二度目の定義の場所だけを示します。見出し（「『X』とは」）は語を掲げるだけなので、定義として数えません。

     → 定義を一か所にまとめ、もう一方は「第2条に定める備品」のように参照にしてください。意図して意味を変えているなら、別の語にします。

     このルールをゆるめる:  npx chaff relax duplicate-definition


────────────────────────────────────────────────────────────

  エラー 2 件、注意 1 件   すべて機械による判定です
              （同じ文章なら何度実行しても同じ結果になります）

  文章は書き換えていません。直すのは書いた人です。

  試験中の rule を 7 件、ジャンルの既定で有効にしています: dangling-figure-reference, dangling-reference, date-range-reversed, date-weekday-mismatch, duplicate-definition, numbering-gap, total-mismatch

  {not-run}
```

## 指摘の読み方

指摘は 3 件です。`✖` はエラー、`⚠` は注意を表します。

| 行 | 指摘 | 意味 | 直しかた |
| --- | --- | --- | --- |
| 10 | 参照先が無い | 第9条はこの規程にありません | 正しい条の番号に直すか、台帳の条を足します |
| 12 | 番号の抜け・重なり | 第2条の次が第4条で、第3条がありません | 番号を振り直します。欠番として残すなら「第3条（削除）」と書きます |
| 15 | 同じ語の二重定義 | 「備品」を 6 行目でも定義しています | 定義を一か所にまとめます |

## 「動いていない」一覧の読み方

画面の最後には、今回見なかったルールが理由つきで並びます。
「指摘なし」を「全部見て問題なし」と取り違えないためです。理由は 3 種類です。

| 理由 | 意味 |
| --- | --- |
| ジャンル legal/statute では見ないため | 規程では決まった書き方なので、わざと見ていません |
| ja 向けの rule ではないため | 英語の文書だけに使うルールです |
| まだ試験中のため | 誤りが出ないか確かめている最中のルールです。`--experimental` を付けると動きます |

その上の「試験中の rule を 7 件、ジャンルの既定で有効にしています」は、ほかのジャンルではまだ試験中の 7 件です。
規程で確かめてあるので、このジャンルでは動かします。

## ジャンルを毎回書かずに済ませる

`--genre` を付けないと、chaff は技術記事（`blog/tech`）として見ます。
規程に見えるときは、1 行目の下に勧めが出ます。

```
$ npx chaffjs kitei.md

kitei.md   blog/tech · 日本語   ジャンルは既定から
   法令・規程のようです。--genre legal/statute を試せます
```

このとき、条番号のルールは動いていません。指摘が出ないのはそのためです。
毎回 `--genre` を書く代わりに、フォルダにジャンルを書いた設定ファイルを置けます。

```bash
npx chaffjs init --genre legal/statute    この場所に chaff.yaml を作り、ジャンルを書く
```

`chaff.yaml`（設定ファイル）と `.gitignore` を作ったと出たあとに、次が出ます。

```
ジャンルは legal/statute にしました。違う場合は chaff.yaml の genre を直してください。
  一覧: npx chaff genres

次:
  npx chaff .            この場所の Markdown を全部見る
```

これで、このフォルダでは `npx chaffjs kitei.md` だけで規程として見ます。

## 意図した箇所を黙らせる

指摘は正しくても、そこだけは意図してそうしている、ということがあります。
たとえば第3条を削除したが、ほかの規程が第4条を引いているので番号を変えたくない場合です。
その見出しのすぐ上に、次の 1 行を書きます。

```markdown
<!-- stet: numbering-gap — 旧第3条は削除した。ほかの規程が第4条を引いているので番号を変えない -->
## 第4条（返却）
```

`stet` は、この箇所の指摘を黙らせる印です。`—` の後ろに理由を書きます。
Markdown のコメントなので、文書を開いた人の画面には出ません。
かけ直すと、番号の指摘が消え、1 行目に黙らせた件数が出ます。
ここでは `--compact` を付け、1 件を 2 行にまとめて出しています。

```
$ npx chaffjs kitei.md --genre legal/statute --compact

kitei.md   legal/statute · 日本語   ジャンルは--genreから   stet 1 件

  10:5    error   「第9条」（番地 9）はこの文書にありません
                  dangling-reference
  16:11   warning 「備品」は 6 行目でも定義されています
                  duplicate-definition

指摘 2 件、動いていない rule 48 件
```

## チームで決まりを変える

黙らせるのが 1 箇所ではなく、チームの決まりなら、ルールのほうを変えます。
たとえば、削除した条の番号を詰めない決まりなら、番号の抜けは誤りではありません。
ゆるめる（`relax`）を、理由をつけて打ちます。

```bash
npx chaffjs relax numbering-gap --why "削除した条の番号を詰めない決まりのため"
```

画面には、次のように出ます。

```
numbering-gap を relaxed にしました（…/chaff.yaml）
このルールに数の上限はありません。指摘は消えず、エラー ではなく 注意 として出ます。
```

条番号のルールは、数を数えません。番号が飛んでいるか、いないかを見るだけです。
そのため、ゆるめると指摘の重さが一段下がります。指摘は消えないので、抜けた番号は見えたままです。
`chaff.yaml` には、次の行が理由と日付と打った人の名前つきで書き足されます。

```yaml
  # 番号の抜け・重なり
  # 第3条の次が第5条、(a) の次が (c)、同じ第2項が二つ。番号が飛ぶか重なると、読み手は何かが消えたのか、参照がどちらを指すのかを判断できません。同じ親の中で並ぶ番号だけを比べます。枝番号（第3条の2）は並びの外として扱います。
  numbering-gap: relaxed # 2026-09-30 削除した条の番号を詰めない決まりのため / isamu
```

stet を書く前の `kitei.md` にかけ直すと、番号の指摘が `error` から `warning` に変わります。

```
$ npx chaffjs kitei.md --compact

kitei.md   legal/statute · 日本語   ジャンルはchaff.yamlから

  10:5    error   「第9条」（番地 9）はこの文書にありません
                  dangling-reference
  12:1    warning 「第2条」の次が「第4条」です（3 番目のはず）
                  numbering-gap
  15:11   warning 「備品」は 6 行目でも定義されています
                  duplicate-definition

指摘 3 件、動いていない rule 48 件
```

エラーが 1 件でも残ると、chaff は失敗で終わります。注意だけなら成功で終わるので、CI を止めません。
ここでエラーが残っているのは、参照先の無い第9条のほうです。

番号の抜けをまったく見なくてよいなら、`off` で止めます。

```bash
npx chaffjs off numbering-gap --why "条番号は別の台帳で管理しているため"
```

止めたルールは、かけ直すと「設定で止めているため」として、動いていない一覧に並びます。
どちらの場合も理由がファイルに残るので、後から来た人も、なぜ変えたのかを追えます。

## 直したあと

番号を振り直し、台帳の条を足し、定義を第1条にまとめました。

```markdown
# 備品管理規程

## 第1条（目的）

この規程は、会社の備品の貸出と返却の手続きを定める。
２　この規程において「備品」とは、会社が所有するパソコン、カメラその他の機器のうち、1万円以上のものをいう。

## 第2条（貸出）

社員は、第4条に定める台帳に記入して、備品を借りることができる。

## 第3条（返却）

借りた備品は、借りた日から7日以内に返さなければならない。

## 第4条（台帳）

総務部は、備品の貸出と返却を記録する台帳を備える。
```

```
$ npx chaffjs kitei-fixed.md --genre legal/statute

kitei-fixed.md   legal/statute · 日本語   ジャンルは--genreから

────────────────────────────────────────────────────────────

  指摘はありません   すべて機械による判定です
              （同じ文章なら何度実行しても同じ結果になります）

  文章は書き換えていません。直すのは書いた人です。

  試験中の rule を 1 件、設定により有効にしています: numbering-gap

  試験中の rule を 6 件、ジャンルの既定で有効にしています: dangling-figure-reference, dangling-reference, date-range-reversed, date-weekday-mismatch, duplicate-definition, total-mismatch
```

この下に並ぶ「動いていない」一覧は、直す前と同じです。

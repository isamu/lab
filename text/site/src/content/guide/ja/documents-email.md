# 仕事のメールでできること

仕事のメールは、相手に一つ頼みごとをして、返事をもらうための文書です。
chaff は、丁寧にしようとして増える言い回しや、送る前に埋め忘れた所を機械で見つけます。
ジャンルは `business/email` です。手紙も同じジャンルで見ます。

## メールでよく起きること

メールは、丁寧に書こうとするほど、頼みごとが文の奥に沈みます。

| 書き癖 | 例 |
| --- | --- |
| 長い一文 | 「〜の件につきまして、〜いただきたく、〜できないかと思い、ご連絡いたしました」 |
| 「させていただく」の重なり | 「ご紹介させていただきます」「送付させていただきます」「ご案内させていただきます」 |
| 二重の敬語 | 「ご覧になられた」（「ご覧になった」で足ります） |
| 埋め忘れ | ひな形の「[担当者名]」が、そのまま残っている |

最後の埋め忘れは、送ってしまうと取り返せません。

## chaff が見ること、見ないこと

このジャンルで見る主なルールは、次のとおりです。

| ルール | 見つけるもの | 動く条件 |
| --- | --- | --- |
| `max-sentence-length` | 長すぎる一文（このジャンルでは 70 字まで） | いつも（info） |
| `sasete-itadaku` | 「させていただく」を使った文の多さ | いつも（info） |
| `double-keigo` | 二重の敬語 | いつも |
| `unfilled-placeholder` | 「[担当者名]」のような、埋めていない空欄 | いつも |
| `risk-disclosure` | よいことだけを書き、気をつけることを書いていない文書 | `npx chaffjs test` で AI に読ませたとき |

見ないことも決めてあります。

- 宛名や会社名が正しいかは見ません。「山田様」が本当に山田さんかは、送る人が確かめます。
- 文書のどの日付にも年が無いときは、曜日を確かめません。この例の「10月10日（金）」は、どの年か決まらないからです。年まで書いた日付が一つでもあれば、年の無い日付はその日付から 5 か月以内になる年として、曜日を確かめます。
- 敬語が場面に合っているか（へりくだりすぎていないか）は決めません。数が多い所を示すだけです。
- 添付を忘れたかは見ません。chaff が読むのは本文だけです。

## かけてみる

準備がまだなら、先に[準備する](./documents#準備する)を済ませます。
メールの本文をテキストエディタに貼り、`mail.md` という名前で保存しました。

```markdown file=mail.md
件名：打ち合わせ日程のご相談

株式会社みなと商事
営業部 山田様

いつも大変お世話になっております。ささき制作の佐々木です。

先日はお忙しいところ、お時間をいただき誠にありがとうございました。

さて、先日お話しさせていただいたサイトの改修の件につきまして、改めてご説明する機会をいただきたく、打ち合わせのお時間を頂戴できないかと思い、ご連絡いたしました。

当日は、弊社のデザイナーからも案をご紹介させていただきます。

お手数をおかけして恐縮ですが、もし差し支えなければ、下記の日程からご都合のよい日をお知らせいただけますと幸いです。

- 10月6日（火）14時から
- 10月8日（木）10時から
- 10月10日（金）16時から

前回の資料は、本日あらためて送付させていただきます。ご覧になられた資料について、ご不明な点がございましたら、[担当者名]までお気軽にお問い合わせください。

日程が決まりましたら、会議室の場所をご案内させていただきます。

何卒よろしくお願い申し上げます。

佐々木
```

ジャンルを付けずにかけると、1 行目の「件名：」を見て、メールのジャンルを勧めます。
`--compact` は、1 件を 2 行にまとめて出す印です。

```
$ npx chaffjs mail.md --compact

mail.md   blog/tech · 日本語   ジャンルは既定から
   メール・手紙のようです。--genre business/email を試せます

  10:1    info    「させていただく」が文書内に 4 回あります（3 回まで）
                  sasete-itadaku
  12:1    info    「させていただく」が文書内に 4 回あります（3 回まで）
                  sasete-itadaku
  20:1    info    「させていただく」が文書内に 4 回あります（3 回まで）
                  sasete-itadaku
  20:55   warning 「[担当者名]」が埋まっていません
                  unfilled-placeholder
  22:1    info    「させていただく」が文書内に 4 回あります（3 回まで）
                  sasete-itadaku

{counts}
```

技術ブログとして読んだので、メールの短い一文の上限と、二重の敬語はまだ見ていません。
勧められたとおり、ジャンルを付けてかけます。

```
$ npx chaffjs mail.md --genre business/email --compact

mail.md   business/email · 日本語   ジャンルは --genre から

  10:1    info    この文は 80 文字あります（70 文字まで）
                  max-sentence-length
  10:1    info    「させていただく」が文書内に 4 回あります（3 回まで）
                  sasete-itadaku
  12:1    info    「させていただく」が文書内に 4 回あります（3 回まで）
                  sasete-itadaku
  20:1    info    「させていただく」が文書内に 4 回あります（3 回まで）
                  sasete-itadaku
  20:27   warning 「ご覧になられる」は敬語が二重になっています
                  double-keigo
  20:55   warning 「[担当者名]」が埋まっていません
                  unfilled-placeholder
  22:1    info    「させていただく」が文書内に 4 回あります（3 回まで）
                  sasete-itadaku

{counts}
```

`info` は、読み飛ばしてもよい情報です。実行を失敗にはしません。
人の書いた文書にもよく出る指摘なので、この重さにしてあります。

## 最初に出る指針

ジャンルを決めると、chaff は結果の最初にそのジャンルの指針を出します。
よいメールが満たすことを、原稿を確かめる問いの形で並べたものです。
その下に、このジャンルで特に効く rule の名前が 1 行で出ます。

問いの多くはルールでは確かめられないので、指摘より先に読みます。
AI に書き直させるときも、AI は同じ指針に沿って書きます（[AI にジャンルの指針を渡す](./ai-sounding#ai-にジャンルの指針を渡す)）。

```
$ npx chaffjs mail.md --genre business/email

指針: メール・手紙（business/email）

  下の指摘より先に、原稿がこれを満たしているかを確かめてください。

  - 件名と最初の 2 行で、用件と、相手にしてほしいことが分かるか
  - 依頼ごとに期限があるか（「近日中」ではなく日付で）
  - 「添付します」と書いたものを、本当に添付しているか
  - 宛名・挨拶・結び・署名がそろっているか

  このジャンルで特に効く rule: attachment-not-attached, cushion-phrase-density, due-before-issue, email-greeting-closing, email-subject-length, preamble-length, request-without-deadline, risk-disclosure, unsourced-number
  chaff.yaml の guide: で書き換えられます。出さないときは --no-guide。

════════════════════════════════════════════════════════════

mail.md   business/email · 日本語   ジャンルは --genre から
…
```

パスや内容から推測したジャンルと、既定のジャンルでは、指針を出しません。
違う種類の文書の指針は、かえって読み手を迷わせるためです。
`--compact` と `--no-guide` でも出しません。
指針の文は、チームが `chaff.yaml` の `guide:` で書き換えられます（[ジャンルの指針を変える](./configuration#ジャンルの指針を変える)）。

## 指摘の意味と直しかた

| 行 | 指摘 | 意味 | 直しかた |
| --- | --- | --- | --- |
| 10 | `max-sentence-length` | 一文が 80 字あり、頼みごとが文の最後まで出てきません | 2 文に分け、頼みごとを先に書きます。「改修の件で、打ち合わせのお時間をいただけないでしょうか。」 |
| 10、12、20、22 | `sasete-itadaku` | 「させていただく」を使った文が 4 つあります | 「ご紹介します」「お送りします」「ご案内します」と、ふつうの丁寧語にします |
| 20 | `double-keigo` | 「ご覧になる」に「られる」を重ねています | 「ご覧になった資料」にします |
| 20 | `unfilled-placeholder` | ひな形の空欄が残っています | 担当者の名前を入れます。送る前に、必ず直します |

「させていただく」は、一度なら丁寧です。重なると、誰が決めて何をするのかが見えにくくなります。
chaff は、この言い回しを使った文を数えています。1 文に 2 回あっても、1 つと数えます。

## 意味を読む検査は AI に頼む

`npx chaffjs test` を使うと、気をつけることを書いていないかを AI に読ませます。
`npx chaffjs test mail.md --genre business/email --dry-run` で確かめると、1 箇所を送ると出ます。
日程の相談のメールなら、気をつけることが無くても困りません。AI の答えを読んで、要るかどうかを決めます。

## chaff.yaml の始め方

メールの下書きを置くフォルダに、次の `chaff.yaml` を置きます。

```yaml
genre: business/email
language: ja
```

この `chaff.yaml` を置くと、`npx chaffjs mail.md --compact` だけで、上の指摘がすべて出ます。
`--genre` を毎回付けなくて済みます。

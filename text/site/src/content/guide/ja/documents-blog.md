# 技術記事（Zenn・Qiita）でできること

技術記事は、自分が試したことや直したことを、ほかの開発者に向けて書く文書です。
chaff は、読み手を待たせる書き出しや、生成文によく出る形を機械で見つけます。
ジャンルは `blog/tech` です。ジャンルを決めないときも、chaff はこのジャンルで見ます。

## 技術記事でよく起きること

技術記事は、AI に下書きを頼むことが増えました。そのまま出すと、生成文の形が残ります。

| 書き癖 | 例 |
| --- | --- |
| どの記事にも当てはまる書き出し | 「近年、開発の現場ではコンテナがますます当たり前になっています」 |
| 予告だけの文 | 「ポイントは、」「重要なのは、」「正直に言うと、」 |
| 誰も言っていないことを打ち消す対比 | 「これは単なる待ち時間ではありません」 |
| 数が合わない予告 | 「直したことは以下の 2 つです」の下に、箇条書きが 3 つある |
| 行き先の無いリンク | 記事の中に無い見出しへのリンク |
| 決まり文句の結び | 「いかがでしたでしょうか」「お役に立てれば幸いです」 |

## chaff が見ること、見ないこと

このジャンルで見る主なルールは、次のとおりです。

| ルール | 見つけるもの | 動く条件 |
| --- | --- | --- |
| `padded-intro` | どの記事にも当てはまる書き出し | いつも |
| `closing-cliche` | 決まり文句の結び | いつも |
| `announcing-opener` | 「ポイントは、」のような予告で始まる文の重なり | `--experimental` を付けたとき |
| `contrast-framing` | 「単なる X ではなく」のような対比の重なり | `--experimental` を付けたとき |
| `colon-lead-in` | コロンで箇条書きへ渡す文の多さ | `--experimental` を付けたとき |
| `ai-generated-composite` | 生成文の形が、一つの記事に 3 種以上そろったこと | `--experimental` を付けたとき |
| `announced-count-mismatch` | 予告した数と、箇条書きの数の食い違い | `--experimental` を付けたとき |
| `broken-link` | 記事の中に無い見出しへのリンク | `--experimental` を付けたとき |
| `latin-spacing` | 日本語と英数字の間の空白の、付け方の揺れ | `--experimental` を付けたとき |
| `empty-conclusion` | 中身の無い結び | `npx chaffjs test` で AI に読ませたとき |

見ないことも決めてあります。

- コードが動くかは見ません。コマンドや設定の値が正しいかは、書いた人が試して確かめます。
- 数字が本当かは見ません。「9 分から 2 分」が測った値どおりかは、書いた人が確かめます。
- 外のサイトへのリンクが開けるかは見ません。見るのは、記事の中の見出しへのリンクだけです。
- 「AI が書いた」とは判定しません。生成文に多い形が重なった所を、読み返す目印として示すだけです。

## かけてみる

準備がまだなら、先に[準備する](./documents#準備する)を済ませます。
次の記事を `kiji.md` という名前で保存しました。この記事は、このページのために書いたものです。

```markdown file=kiji.md
# Docker のビルドを速くした話——キャッシュという見落とされがちな鍵

近年、開発の現場ではコンテナがますます当たり前になっています。本記事では、私たちのチームが Docker のビルド時間を短くした方法を詳しく解説していきます。

## 何が問題だったのか

CI でのビルドに、毎回**約 9 分**かかっていました。

これは単なる待ち時間ではありません。**開発の速さそのものを奪う問題**です。

正直に言うと、私たちは半年ほどこの問題を見ないふりをしていました。気づけば、待ち時間で一日に何十分も溶かしていました。

## 原因

ポイントは、Dockerfile の書く順番です。

調べて分かったことは次の通りです：

- `COPY . .` を `RUN yarn install` より前に書いていた
- そのため、ソースを1行変えるだけで依存の入れ直しが走っていた
- CI では前回のキャッシュを使っていなかった

重要なのは、キャッシュが黙って捨てられていたことです。ビルドは失敗せず、静かに遅くなっていました。

## 直したこと

直したことは以下の 2 つです：

- `package.json` と `yarn.lock` だけを先に `COPY` し、依存を入れてからソースを `COPY` する
- `docker build` に `--cache-from` を付け、前回のイメージをキャッシュとして使う
- `.dockerignore` に `node_modules` を足す

さらに、ビルドの結果を `docs/build-time.md` にまとめました。詳しくは[ビルド時間の記録](#ビルド時間の記録)を見てください。

## 結果

ビルドは 9 分から 2 分になりました。単に速くなっただけでなく、チームの生産性も飛躍的に向上しました。

いかがでしたでしょうか。この記事が皆さんのお役に立てれば幸いです。
```

## 指摘の意味と直しかた

| 行 | 指摘 | 意味 | 直しかた |
| --- | --- | --- | --- |
| 3 | `padded-intro` | 「近年、」は、どの記事にも書ける書き出しです | 何に困っていたかから書き始めます。「CI のビルドに毎回 9 分かかっていました」 |
| 9、37 | `contrast-framing` | 「単なる X ではありません」と、誰も言っていないことを打ち消しています | 打ち消しを消し、言いたいことだけを書きます |
| 11、15、23 | `announcing-opener` | 「正直に言うと」「ポイントは」「重要なのは」と、予告で文を始めています | 予告を消し、中身から書き始めます |
| 17、27 | `colon-lead-in` | 「次の通りです：」と、コロンで箇条書きへ渡す文が続いています | 箇条書きの項目がつながっているなら、文に戻してつながりを書きます |
| 20 | `latin-spacing` | ほかは「9 分」と空けているのに、「1行」だけ詰めています | 「1 行」と空けて、記事の中で揃えます |
| 27 | `announced-count-mismatch` | 「2 つ」と書いたのに、箇条書きは 3 つあります | 数か箇条書きの、違うほうを直します |
| 33 | `broken-link` | 「ビルド時間の記録」という見出しが、記事にありません | 見出しを足すか、リンクを外します |
| 39 | `closing-cliche` | 結びの決まり文句です | 消して、読み手が次にすることで終えます |
| 1 | `section-length-uniformity` | 節の長さが揃いすぎています | 中身の多い節を厚くします。長さを合わせるために文を足しません |
| 11 | `ai-generated-composite` | 上の形が、一つの記事にいくつもそろいました | 部分直しで足りなければ、記事を書き直します（下の節） |

`--experimental` を付けたときに出るのは、まだ試験中のルールです。
誤りが出ないかを確かめている最中なので、既定では動きません。
「一日に何十分も溶かしていました」「静かに遅くなっていました」のような比喩も生成文に多い形です。
この記事では、chaff はこれを指摘していません。機械は、書き癖をすべて見つけるわけではありません。

## 生成文の形が多いときは書き直す

指摘を一つずつ消しても、太字と箇条書きが続く記事は生成文に読めます。
そのときは、節ごとに書き直します。
手順は [AIっぽさを直す](./ai-sounding) にあります。

| 直し方 | 直すもの | 向いているとき |
| --- | --- | --- |
| 部分直し | 指摘された所だけ | 中身も構成もよく、言い回しだけが気になるとき |
| 書き直し | 節ごとに、記事の全体の形 | 部分直しをしても、まだ生成文に読めるとき |

書き直したあとは、`npx chaffjs compare kiji.md 書き直した記事.md` で、数やコマンドが落ちていないかを確かめます。
書き直しの例と `compare` の画面も、同じページにあります。

## 意味を読む検査は AI に頼む

「結果」の節の結びに中身があるかは、意味を読まないと決まりません。
`npx chaffjs test` は、機械で絞り込んだ箇所だけを AI に送ります。
`--dry-run` を付けると、送らずに、送る箇所を確かめられます。

```bash
npx chaffjs test kiji.md --genre blog/tech --dry-run    AI に送る箇所を見せる（送らない）
```

画面の前半は、機械の検査と同じです。その後に、次が出ます。

```
kiji.md   全 24 文のうち 1 箇所を送ります（API は呼んでいません）

      1 箇所  結びに中身がない  （機械で絞り込み済み）

  最初の 1 件に送る文章:

    ビルドは 9 分から 2 分になりました。単に速くなっただけでなく、チームの生産性も飛躍的に向上しました。

    いかがでしたでしょうか。この記事が皆さんのお役に立てれば幸いです。


────────────────────────────────────────────────────────────

  合計 1 箇所を送ります。--dry-run なので API は呼んでいません。
  送り先: anthropic / claude-opus-5（認証なし）
```

実際に AI に読ませるには、API key が要ります。置き方は [README](https://github.com/isamu/lab/tree/main/text#readme) にあります。

## chaff.yaml の始め方

技術記事を置くフォルダに、次の `chaff.yaml` を置きます。
上で `--experimental` を付けて出た試験中のルールのうち、技術記事で役に立つものを、いつも動かす設定です。

```yaml
genre: blog/tech
language: ja

rules:
  ai-generated-composite: normal
  announcing-opener: normal
  contrast-framing: normal
  colon-lead-in: normal
  announced-count-mismatch: normal
  broken-link: normal
  latin-spacing: normal
```

この `chaff.yaml` を置くと、`npx chaffjs kiji.md --compact` だけで、上の指摘が出ます。
`section-length-uniformity` だけは入れていないので出ず、`ai-generated-composite` が数える形からも外れます。
チームで書き方を決めたら、[チームの表記ルールを決める](./house-style) を読んで書き足します。

# chaff の手引きを書くときの決まり

手本は chaff の `README.md` です。chaff で測り、
機械で確かめる決まりは `chaff.yaml` に、機械が確かめられない決まりはこの文書に書きました。

## 誰に・何のために

読み手は chaff を初めて使う人です。文章を書く人で、エンジニアとは限りません。

読み終えたとき、読み手が次の 3 つをできるようにします。

- 自分の文章に chaff をかける
- 設定を自分のチームに合わせる
- 指摘の意味が分かる

コマンドを知らない人も読みます。コマンドを出すときは、何が起きるかを同じ場所に書きます。
手本の「`npx chaffjs .` この場所の Markdown を全部見る」のように、コマンドの横に一言添えます。

## 語調と文末

- **です・ます で書きます。** 手本は「設定ファイルも API key も言語の指定も要りません。」のように、
  始めから終わりまで です・ます です。
- **言い切ります。** 手本は「文章は書き換えません。直すのは書いた人です。」と、
  ぼかさずに書いています。「〜かもしれません」を重ねません。
- **読み手を「あなた」と呼びません。** 手本は主語を立てず、
  「指摘されたら」のように、読み手がすることを直接書きます。
- **理由を一緒に書きます。** 手本は「見る文書が一つも見つからなければ失敗にします。
  CI が何も見ないまま通る状態を作らないためです。」のように、決まりのすぐ後に理由を置きます。
- **一文を短くします。** 長くても 85 字に収めます。長くなったら文を分けます。

## 用語と表記

- **日本語と英数字の間には半角の空白を入れます。** 手本は「Node.js 24 以上」「指摘が 0 件でも」と一貫しています。
  数字と単位の間も同じです。
- **「API key」と書きます。** 手本は key をカタカナで書いていません。
- **rule の名前、コマンド、ファイル名はそのまま書き、コードの印で囲みます。**
  手本の `heading-echo`、`chaff.yaml`、`npx chaffjs relax` の書き方に合わせます。
- **4 つの強さは英語のまま書きます。** `strict` `normal` `relaxed` `off` です。
  設定ファイルにそのまま書く語なので、訳しません。
- **数字は算用数字で書きます。** 手本は「応じ方は 3 つあります」と書いています。
- **定着している言い方を使います。** 「閾値」「棚上げ」「黙らせる」「ゆるめる」です。
  いったん決めた言い方を、同じ文書の中で言い換えません。
- **「ルール」と書き、rule の名前だけ英語にします。** 画面に出る言葉に合わせるためです。
  機械には確かめさせていません。

## 構成

- **冒頭は一段落で、それが何かを言います。** 手本は「chaff は、文書の読みにくいところと、
  機械で確かめられる誤りを見つける道具です。」と書き始め、前置きを置きません。
- **見出しは 2 段まで**（`#` と `##`）です。手本は `###` を使っていません。
- **見出しは、読み手がしたいことか、知りたいことにします。** 手本の「かけてみる」
  「指摘されたら」「文書の種類を選ぶ」のような見出しです。
- **コマンドを見せたら、実際の出力も見せます。** 手本は、コマンドの次に出力をそのまま載せています。
  読み手は、自分の画面と見比べて確かめられます。
- **並べるものが 3 つ以上で、それぞれに説明があるときは表にします。**
  手本の「直す・黙らせる・ルールを変える」の表がその例です。
- **一段落は 4 文までにします。**
- 手本の `README.md` には開発者向けの節（開発）も入っています。
  手引きは読み手が違うので、開発者向けの内容は入れません。

## 機械が確かめること

`chaff.yaml` で、ジャンルは `technical/readme`、言語は日本語にしています。
ここに書いたものは chaff が確かめます。それ以外の節に書いたことは、書く人が守ります。

| rule | 設定 | 見つけるもの |
| --- | --- | --- |
| `max-sentence-length` | 85 字（既定は 100） | 長すぎる一文 |
| `max-paragraph-length` | 4 文（既定は 5） | 文を詰めすぎた段落 |
| `max-kanji-continuous` | `strict`（6 字） | 漢字が続きすぎている所 |
| `repeated-sentence-head` | `strict`（2 回） | 同じ書き出しの文が続く所 |
| `no-mixed-desumasu` | `strict` | です・ます と だ・である の混在 |
| `latin-spacing` | `normal` | 日本語と英数字の間の空白の付け方が揃っていない所 |
| `preferred-term` | `normal` | 「API キー」「APIキー」（「API key」に直す） |

上にない rule は、ジャンルの既定のまま動きます。語調、見出しの付け方、表にするかどうか、
「ルール」と「rule」の使い分けは、機械では確かめていません。

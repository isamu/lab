# プレスリリース・お知らせでできること

プレスリリースやお知らせは、日付、数、料金を、社外の人に一度で正しく伝える文書です。
chaff は、日付と曜日、期間、合計、割合、予告した数の食い違いを機械で見つけます。
ジャンルは `business/press-release` です。社内のお知らせも同じジャンルで見ます。

## プレスリリースでよく起きる崩れ

プレスリリースは、出す直前まで日付や料金が動きます。直した数と、直し忘れた数が並びます。

| 崩れ | 例 |
| --- | --- |
| 曜日が合わない | 提供開始日を 1 日ずらしたのに、曜日を直していない |
| 期間が逆になる | 「10月26日〜10月19日」と、始まりと終わりを取り違えた |
| 合計が合わない | オプションの料金を直したのに、合計を直していない |
| 割合が 100% にならない | 内訳を一つ直したら、足して 95% になった |
| 予告した数が合わない | 「特長は次の 4 つ」の下に、3 つしか書いていない |

社外に出た後で直すと、訂正のお知らせを出すことになります。

## chaff が見ること、見ないこと

このジャンルで見る主なルールは、次のとおりです。どれも、設定を書かなくても動きます。

| ルール | 見つけるもの |
| --- | --- |
| `date-weekday-mismatch` | 日付に添えた曜日が、暦と合っていない所 |
| `date-range-reversed` | 期間の終わりが始まりより前の所 |
| `total-mismatch` | 合計が内訳の和と合わない所 |
| `percent-sum-mismatch` | 内訳の割合を足しても 100% にならない所 |
| `announced-count-mismatch` | 予告した数と、すぐ下の箇条書きの数の食い違い |
| `risk-disclosure` | よいことだけを書き、気をつけることを書いていない文書（`npx chaffjs test` で AI に読ませたとき） |

見ないことも決めてあります。

- 数字が事実と合っているかは見ません。「社員 400 人」が本当に 400 人だったかは、書いた人が確かめます。
- 文書のどの日付にも年が無いときは、曜日を確かめません。どの年か決まらないからです。年まで書いた日付が一つでもあれば、年の無い日付はその日付から 5 か月以内になる年として、曜日を確かめます。
- 割合は、表の見出しや、すぐ上の文に「内訳」「構成比」「シェア」のような語があるときだけ足します。
  伸び率や利用率のように、足しても 100% にならない割合があるからです。

## かけてみる

準備がまだなら、先に[準備する](./documents#準備する)を済ませます。
次のプレスリリースを `release.md` という名前で保存しました。会社とアプリの名前は架空です。

```markdown file=release.md
# 会議室予約アプリ「よやくん」を11月に提供開始

2026年10月15日
株式会社みなと商事

株式会社みなと商事は、会議室の予約をスマートフォンから行えるアプリ「よやくん」の提供を、2026年11月2日（火）に始めます。

## 開発の背景

当社が9月に社員 400 人に行った調査では、会議室の予約に不満があると答えた人が多くいました。

| 不満の内容 | 内訳 |
| --- | --- |
| 空いている部屋が探しにくい | 45% |
| 予約の取り消しが面倒 | 30% |
| その他 | 20% |

## 主な特長

よやくんの特長は次の 4 つです。

- 空いている部屋を地図で探せる
- 予約の取り消しが 1 回の操作で済む
- 社内の SSO でログインできる

## 先行体験会

提供開始に先立ち、先行体験会を開きます。

- 期間：2026年10月26日〜2026年10月19日
- 会場：本社 1 階 ロビー

## 料金

| プラン | 月額 |
| --- | --- |
| 基本プラン | 30,000円 |
| 地図オプション | 5,000円 |
| 合計 | 36,000円 |

## お問い合わせ

株式会社みなと商事 広報部
```

ジャンルを付けてかけます。
`--compact` は、1 件を 2 行にまとめて出す印です。

```
$ npx chaffjs release.md --genre business/press-release --compact

release.md   business/press-release · 日本語   ジャンルは --genre から

  6:45    error   「2026年11月2日」は月曜日です（火曜日と書いてあります）
                  date-weekday-mismatch
  14:19   warning 内訳の割合の和が 95% で、100% になりません
                  percent-sum-mismatch
  20:12   warning 「4 つ」と予告していますが、すぐ下の箇条書きは3項目です
                  announced-count-mismatch
  30:6    warning 期間「2026年10月26日〜2026年10月19日」の終わりが始まりより前です
                  date-range-reversed
  39:8    error   合計「36,000円」が、内訳の金額の和（35,000円）と合いません
                  total-mismatch

{counts}
```

`error` は、数が食い違っていて、どちらかが必ず間違っている所です。
`warning` は、直したほうがよい所です。

## 最初に出る指針

ジャンルを決めると、chaff は結果の最初にそのジャンルの指針を出します。
よいプレスリリースが満たすことを、原稿を確かめる問いの形で並べたものです。
その下に、このジャンルで特に効く rule の名前が 1 行で出ます。

問いの多くはルールでは確かめられないので、指摘より先に読みます。
AI に書き直させるときも、AI は同じ指針に沿って書きます（[AI にジャンルの指針を渡す](./ai-sounding#ai-にジャンルの指針を渡す)）。

```
$ npx chaffjs release.md --genre business/press-release

指針: プレスリリース・お知らせ（business/press-release）

  下の指摘より先に、原稿がこれを満たしているかを確かめてください。

  - 見出しと第 1 段落で、誰が・何を・いつ・どこで・なぜを言い切っているか
  - 日付・価格・数字・固有名詞が正確で、本文の中で一致しているか
  - 強い形容（画期的・業界初）に裏付けがあるか
  - 問い合わせ先と、発表の日付を書いているか

  このジャンルで特に効く rule: cushion-phrase-density, preamble-length, quote-unnamed-speaker, request-without-deadline, risk-disclosure, unsourced-number
  chaff.yaml の guide: で書き換えられます。出さないときは --no-guide。

════════════════════════════════════════════════════════════

release.md   business/press-release · 日本語   ジャンルは --genre から
…
```

パスや内容から推測したジャンルと、既定のジャンルでは、指針を出しません。
違う種類の文書の指針は、かえって読み手を迷わせるためです。
`--compact` と `--no-guide` でも出しません。
指針の文は、チームが `chaff.yaml` の `guide:` で書き換えられます（[ジャンルの指針を変える](./configuration#ジャンルの指針を変える)）。

## 指摘の意味と直しかた

| 行 | 指摘 | 意味 | 直しかた |
| --- | --- | --- | --- |
| 6 | `date-weekday-mismatch` | 2026年11月2日は月曜日です | 曜日を「（月）」に直します。火曜日に始めるなら、日付を 11月3日に直します |
| 14 | `percent-sum-mismatch` | 45%、30%、20% を足すと 95% です | 調査の数字を確かめて、違う数字を直します |
| 20 | `announced-count-mismatch` | 「4 つ」と書いたのに、3 つしかありません | 抜けた特長を足すか、「3 つ」に直します |
| 30 | `date-range-reversed` | 終わりの日が、始まりの日より前です | 「2026年10月19日〜2026年10月26日」と、順番を直します |
| 39 | `total-mismatch` | 30,000円と 5,000円を足すと 35,000円です | 合計か、内訳の金額の違うほうを直します |

6 行目は、どちらが正しいかを chaff は決めません。日付と曜日の、どちらを直すかは書いた人が決めます。
直したら、社外に出す前にもう一度かけて、指摘が消えたことを確かめます。

## 意味を読む検査は AI に頼む

`npx chaffjs test` を使うと、気をつけることを書いていないかを AI に読ませます。
`npx chaffjs test release.md --genre business/press-release --dry-run` で確かめると、1 箇所を送ると出ます。

10 行目の「多くいました」は、何人だったのかを書いていません。
この例では、数字の根拠の検査に送る箇所は 0 箇所で、chaff はここを AI にも送りません。
人が読んで、「400 人のうち 280 人」のように数を書き足します。

## chaff.yaml の始め方

プレスリリースを置くフォルダに、次の `chaff.yaml` を置きます。

```yaml
genre: business/press-release
language: ja

required_sections:
  - お問い合わせ
```

この `chaff.yaml` を置くと、`npx chaffjs release.md --compact` だけで、上の指摘がすべて出ます。
`required_sections` には、どのお知らせにも要る見出しを書きます。
「お問い合わせ」の見出しが無いお知らせは、`required-sections` が指摘します。

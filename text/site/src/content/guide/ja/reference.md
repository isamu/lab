# リファレンス：chaff が見つけられること

chaff が見つけられることを、ルールごとに一覧にしました。
どのルールにも、指摘される文の例と、その例に chaff をかけたときの実際の出力を載せています。
ルールの名前を押すと、そのルールの詳しいページに進みます。
チームの決まりに合うルールが無いときは、[ルールを足す](./adding-rules) を読みます。
ルールが何を根拠にしているかは、[参考文献](./bibliography) にまとめました。
model の出力をこれらの検査で採点する方法は、[AI の評価（AI evals）に使う](./ai-evals) にあります。

## 一覧の見かた

| 印 | 意味 |
| --- | --- |
| 既定で動く | 何も設定しなくても動きます |
| 既定で動く（情報） | 何も設定しなくても動きますが、指摘は「情報」として出ます。実行を失敗にしません |
| 試験中 | まだ測っていない新しいルールです。既定では動きません。下の「試験中のルールを動かす」の方法で動かします |
| chaff.yaml に書いたとき | チームが `chaff.yaml` に書いた語や見出しだけを見ます。書かなければ何も言いません |
| chaff test | 意味を読まないと決まらない検査です。`npx chaffjs test` で AI が読みます |
| 日本語 / 英語 | そのルールが見る文書の言語です |

例の出力は、サイトを作るたびに chaff をかけ直して作っています。
かけるときのジャンルは `business/report` で、試験中のルールと、測ってそのジャンルでは止めたルールも動かしています。
ほかの設定で試した例には、その `chaff.yaml` を添えました。
出力の頭の `1:7` は、例の文の 1 行目 7 字目という意味です。

## どのルールが既定で動くか

ほとんどのルールは、`--experimental` を付けなくても動きます。
どのルールを既定で動かすかは、人が書いた実際の文書（corpus）でそのルールがどれだけ指摘を出すかを測って、機械的に決めています。

- 人の文書にめったに出ないルールは、そのまま動きます。
- 人の文書にもよく出るルールは、「情報」として動きます。読み飛ばしてかまいません。
- あるジャンルの文書の大半に出るルールは、そのジャンルでは止めます。そのジャンルの書き方を言っているだけだからです。止めたルールは「動かなかったルール」に理由つきで並びます。

情報の指摘が要らなければ、そのルールを止めます。

```bash
npx chaffjs off ngram-repetition --why "繰り返しは文体として許す"
```

## 試験中のルールを動かす

試験中のルールは、まだ実際の文書で測っていない新しいルールです。測るまでは既定では止めています。
全部を動かして見るときは、`--experimental` を付けます。

```bash
npx chaffjs --experimental docs/   試験中のルールも動かして見る
```

一つだけ動かすときは、`enable` で名指しします。`chaff.yaml` の `rules` に書き込みます。

```bash
npx chaffjs enable cross-doc-term-variant
```

## 文書が 2 つ以上要るルール、Markdown だけのルール

名前が `cross-doc-` で始まるルールは、一度にかけたファイルどうしを比べます。ある語を 1 つのファイルだけ別の書き方にしている所などです。
ファイルを 2 つ以上か、フォルダを渡したときに動きます。ファイル 1 つでは、動いていないルールに並びます。

Markdown の記法を見るルール（見出しの深さ、画像の代替テキスト、リンクの行き先など）は Markdown の文書でだけ動きます。
`.txt` では「Markdown の文書ではないため」と出して止まります。

どのジャンルで何が動くかは、[ジャンルのページ](../../genres/)にあります。

## 意味を読む検査は chaff test で

結びに中身があるか、数字に根拠があるか、リスクを書いたかは、どれも意味を読まないと決まりません。
chaff は機械で箇所を絞り込み、`npx chaffjs test` でその箇所だけを AI に送って読ませます。
`npx chaffjs test --dry-run 報告書.md` なら、何を送るかを、送る前に画面で確かめられます。
AI を使わなくても、ほかの検査はすべて動きます。
